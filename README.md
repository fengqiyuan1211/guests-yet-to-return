# 致未归的客人

一款以调酒、经营和客人故事为核心的酒馆游戏。玩家按实际步骤制作鸡尾酒、采购有限库存、研发自己的配方，在一次次来访中了解客人，并解锁剧情小游戏与纪念配方。

本仓库是 2026-10-20 提交演示版的完整 Godot 源码工程。

## 启动

1. 使用 **Godot 4.7.2，Compatibility 渲染器**，导入根目录的 `project.godot`。
2. 首次导入需等待素材处理完成，然后按 F5 运行。主入口是 `scenes/title_screen.tscn`。
3. macOS 也可双击 `启动游戏.command`。启动器会查找常见安装位置和 PATH，可用 `GODOT_BIN` 指定 Godot 程序。`启动工作台.command` 是直接进入工作台的开发入口。

剧情、调酒、库存、评分和结算均由本地规则处理。AI 饮后反馈与 DIY 酒图需要配置下面的可选服务；未配置时不影响本地规则计算，酒图生成不可用。

## 演示版流程

- 完成或跳过新手调酒教学后，自动解锁“回响”；营业上架由玩家选择。
- 小线的故事缩为 **3 次来访**：以前演过不少、那局球还没打完、致未归的客人。
- 三段剧情各完成一次送酒，三杯平均总评分**严格高于 60**，才触发小线的正式羽毛球邀请。刚好 60 不满足，练习出杯不计入。
- 羽毛球双方**先得 3 分获胜**。剧情局获胜可获得《童年拾忆》；练习及内测演示不发剧情奖励。
- 其他客人保持 5 次正式剧情的原有流程。
- 角色剧情特调在获得之前不会出现在图鉴或传说研习；普通经典配方仍按原料解锁。
- 旧版小线五轮进度会兼容为三轮，已记录对白与奖励保留；旧版五分比赛记录可以读取，新比赛采用三分规则。

## 可选 AI 服务

需要 Python 3.10 或更新版本。不要把密钥写进 Godot 脚本或提交到 Git。

**DIY 酒图**：在 `services/cocktail-image-service/` 创建虚拟环境，安装 `requirements.txt`，将 `.env.example` 复制为 `.env` 并填写自己的密钥。默认示例模型为 `qwen-image-3.0`。运行 `python run.py`，监听本机 8787 端口。详细说明见该目录 README。

**饮后反馈**：将 `services/customer-feedback-service/.env.example` 复制为 `.env`，填写密钥及账户可用的模型与接口地址，运行该目录的 `python run.py`，监听本机 8788 端口。仅使用 Python 标准库。

游戏支持自动启动本地服务，详见 `docs/本地服务自动启动.md`。更改服务配置后需重启服务。真实生成会使用对应服务商额度；测试默认关闭外部请求。

## 目录

| 目录 | 内容 |
| --- | --- |
| `scenes/`、`scripts/`、`shaders/` | Godot 场景、游戏逻辑和着色器 |
| `assets/` | 运行所需图片、字体、音频及素材署名 |
| `data/` | 配方、原料、剧情、偏好、小游戏配置 |
| `services/` | 可选 Python AI 服务与冻结参考图 |
| `tests/` | 自动验证场景、脚本及隔离存档运行器 |
| `tools/` | 启动、校准和维护工具 |
| `docs/` | 接口、计量与评分说明、提交检查记录 |

## 验证

例如，在仓库根目录执行（将路径替换为本机 Godot）：

```sh
python3 tests/run_unified_story_flow.py --godot /path/to/Godot
python3 tests/run_release_demo.py --godot /path/to/Godot
```

运行器使用 `/tmp` 独立存档，不修改玩家存档。酒图服务的离线测试可在该目录运行 `python -m unittest discover -s tests`。

## 提交与导出

`.gitignore` 排除 `.godot/`、密钥、虚拟环境、服务生成记录、缓存、日志及 `exports/`。保留 `.import` 导入设置和 `.uid` 稳定标识。源码包可由 `python3 tools/package_source.py` 生成到 `exports/`；该包不包含 Git 历史、密钥或本地运行记录。

本仓库是源码提交，不是可直接双击的跨平台安装包。使用 Godot 导出时安装相应平台导出模板，并在非资源文件包含规则中加入 `*.json`、`*.sqlite3`，确保数据目录完整。Python 服务在导出游戏旁单独部署，或配置已部署的服务地址。

玩家存档位于 Godot 的 `user://`，不在源码仓库内。素材署名保留在 `assets/audio/` 下的 README、CREDITS 和来源记录中；没有为第三方素材统一声明新的许可证。
