# 《致未归的客人》连续故事与分支对话 v0.9

这是 Godot 4.7.2 + Compatibility 的主页第一版。工程可以独立打开，也可以把其中的资源复制到桌面项目。

## 查看

1. 打开 Godot，导入本目录里的 `project.godot`。
2. 点击运行项目，或者按 F6 运行当前主页场景。
3. 点击左侧「图鉴」进入单页牛皮纸酒谱，点击牛皮纸左右两侧留白、按 ← / → 或在卡位区域左右滑动翻页。点左侧「酒馆」或按 Esc 返回。商店、研发、酒单、评价仍是入口预览。
4. 初始为 18:00 备料时间；点击「提前开始营业」，时钟约 4 秒快转到 20:00 并迎接随机客人。下方聊天框会出现本次故事和回应选项，点选回应后客人接着讲，点「接着听」推进。收尾点「先聊到这」，再用「再聊一句」闲聊。用「送客，迎接下一位」切换客人；「前往调酒台」仍是入口预览。
5. 点击主页右上角的小老虎机图标，打开牛仔蒸汽风老虎机。点击右侧红色拉杆，或在拉杆获得焦点时按空格键开始。
6. 点击「返回酒馆」旁的问号，展开西部手绘牛皮纸奖赏告示，按图案列出三连和两连奖励，不展示概率。点击「收好告示」、纸外区域或按 Esc 收起。
7. 点击左上角原有星形图标进入设置，时间暂停。点击「继续游戏」返回；「重新开始」需要再点一次「确认重新开始」，才会重置天数、时间、金币、人物相识、故事及老虎机记录。

## 继续游戏与重新开始

- 现在关闭游戏后再启动，会恢复营业天数、具体时间、当前客人、来客队列与对话位置；本次故事已结束时仍保持闲聊，不会因重开而推进下一段。
- 白天、凌晨歇业和提前开店的快进过程也会保存。游戏未运行时，时间不会继续流逝。
- 营业与剧情统一快照保存在 `user://game_session.json`；钱包依旧使用 `wallet.json` 的独立结算保护，`story_progress.json` 保留兼容记录。对话操作立即保存，时钟进度定期自动保存。
- 「重新开始」从第 1 天 18:00、300 金币、所有人物未认识开始。旧记录会自动备份到存档目录的 `backups/`，确认重置前不会清空进度。重置过程如果被中断，下次启动会完成同一次重置。
- 旧版未记录过营业时间，所以首次升级不能还原过去的天数；已有剧情和金币会保留，从本版开始正常记录时间。想完整从头体验，请使用左上角设置中的「重新开始」。

## 连续故事（v0.9）

- 米洛、艾达、老霍克、小线各有一条连续故事，分五次来访展开。每次有三轮分支回应，沿玩家选择显示对应回复。
- 本次故事讲完后客人继续留在酒馆，进入本地闲聊循环。下一章等下次来访才开始。
- 黄色生物仅保留「我是奶龙」→「我才是奶龙」的固定梗。
- 初次见面时姓名、称号和右侧介绍显示「？」。问过称呼、客人自我介绍后才显示身份；黄色生物在回应固定梗后显示身份。认识状态随剧情存档，下次来访不会再隐藏。
- 首次招呼和自我介绍由 `data/guest_introductions.json` 维护，接在第一段故事前，不占五段故事的次数。
- 最新故事在 `data/story_dialogues/`，闲聊在 `data/guest_smalltalk.json`，人物外观和简要介绍在 `data/guests.json`。人物表中的旧三句对白和固定点单已移除；历史偏好字段仅保留为数据参考，当前不展示、不生成订单。
- 剧情存档为 `user://story_progress.json`，与钱包独立。每位客人分别记忆进度，中途退出、送客或歇业会保留没聊完的节点。
- 聊天框显示选项时略增高，底部仍与侧栏对齐；所有普通故事文本和分支沿用已确认的 v0.2 稿件。
- 游戏界面不展示章节编号、总段数、故事标题或流程解释；右侧仅保留人物资料，剧情进度在内部保存。
- Qwen、酒单接口、实际调酒与出杯结算尚待后续实现。已预留 `smalltalk_requested` 和主页 `on_drink_served()` 接口。

数据格式与修改方法见 `data/story_dialogues/README.md`。

## 老虎机规则

每轮扣除 20 金币。先判定隐藏大奖；未触发时，三个转轮分别按「发 3%、金币 7%、酒杯 20%、星星 30%、柠檬 40%」独立抽取。
三个转轮从左到右依次减速停稳，随后统一结算，旋转期间不能重复开始或返回。

| 符号 | 三个相同返还 | 正好两个相同返还 |
| --- | ---: | ---: |
| 发 | 2000 | 120 |
| 金币 | 400 | 50 |
| 酒杯 | 160 | 30 |
| 星星 | 80 | 18 |
| 柠檬 | 40 | 12 |

三连优先、奖励不叠加。两连不限位置；其余组合返还 0。以上均为返还总额，本轮净额还需减去 20 金币。
普通结果的条件期望返还为 16.92703 金币。加入隐藏大奖与保底、且隐藏大奖暂不返还金币时，长期平均返还约 16.71235，净收益约 -3.28765 金币，仍为负期望。

主页余额与老虎机使用同一钱包。金币和待结算结果保存至 Godot 的 `user://wallet.json`。如果转动中关闭程序，下次打开会结算已扣款的那一轮，不会重抽或重复发奖。
初始金币为 300；资金不足时不能启动。本次只实现老虎机，酒馆收入系统后续接入。

## 隐藏大奖（v0.5）

- 最新基础概率为 **0.5% = 0.005 = 1/200**，不是此前提到的 0.0005。
- 连续 99 次未触发后，第 100 次付费转动必中；自然命中或保底命中均重置计数。普通金币中奖不重置隐藏大奖保底。
- 触发时只会生成三个出金金色星徽，不会混出单个或两个。图标参考 CS:GO 出金金色星徽样式重绘为 `assets/slots/rare-gold.svg`。
- 显示「恭喜你，触发隐藏大奖！」并播放大奖灯光和音效。奖项说明纸不显示隐藏奖、概率或保底进度。
- 本轮仍扣 20 金币；隐藏奖不叠加普通三连奖励，暂不发金币或物品，仅持久化一条待配置奖励记录。
- `SlotWallet.hidden_prize_reserved(record)` 在记录保存成功后触发；`get_reserved_hidden_prizes()` 返回已保存记录的深拷贝。记录包含唯一 `id`、`spin`、`pool_id=limited_slot_prize`、`reward_id=null`、`status=reserved`。后续由奖品系统配置实际限定奖品和领取逻辑。
- 保底进度与待结算结果一起原子保存；扣费失败不计次，中途退出按原结果结算一次。v1 钱包保留原金币及待结算金币奖励，隐藏计数从 0 起步，自动迁移至 v2。
- 0.5% 是非保底单次概率；包含百次保底后，长期触发率约 1.2683%。游戏奖项纸不展示这些开发参数。

## 昼夜与营业时间（v0.8）

- 正常速度：现实 1 秒 = 游戏 1 分钟，一晚 8 小时约为现实 8 分钟。
- 初始第 1 天 18:00，先备料；20:00 自动开门迎客，次日 04:00 强制歇业、清走客人并显示本夜来客数量。该数量不等于已完成订单。
- 顶部显示的是营业日：20:00 到次日 04:00 属于同一夜，午夜不换营业日，04:00 后进入下一营业日。
- 非营业时间点击「提前开始营业」，钟面指针、数字时间和环境光线在约 4 秒内一起快转，准确停在 20:00，再恢复正常速度；重复点击不会叠加快进。
- 04:00 会退出正在展示的营业调酒台；商店、图鉴、研发和老虎机页面可以继续使用。老虎机的付费转动不被歇业打断。
- 四张独立场景平滑轮换，按游戏时间连续变化，不在整点硬切。04:00 收工时天色仍暗。

| 游戏时间 | 场景变化 |
| --- | --- |
| 21:00—04:00 | 夜晚，油灯亮起 |
| 04:00—05:30 | 夜晚逐渐过渡到黎明，灯火渐灭 |
| 05:30—06:30 | 独立黎明场景，粉紫晨光、灯已熄灭 |
| 06:30—08:00 | 黎明逐渐变成白天 |

| 18:00—19:00 | 黄昏，暖橙色夕阳 |
| 19:00—21:00 | 黄昏逐渐入夜 |

- 背景使用日景（熄灯版）、原黄昏、夜景、独立黎明四幅对齐素材连续混合；人物随环境轻微调色，菜单和文字保持亮度。

## 开发接口

- `slot_rules.gd`：符号权重、返还与精确期望。
- `slot_wallet.gd`：共享金币、原子保存、待结算记录与恢复。
- `slot_machine.gd`：弹层、拉杆、依次停轮和结果展示。
- `slot_reel.gd` / `slot_lever.gd`：转轮与机械拉杆交互。
- `slot_effects.gd` / `slot_audio.gd`：灯、蒸汽、压力表、齿轮及合成音效。
- `assets/slots/`：可独立编辑的矢量机身与符号素材。

验证：运行 `tests/verify_slots.tscn` 并传入 `--slot-wallet=/tmp/western-slot-test.json`，使用隔离钱包检查 125 种组合期望、扣费、依次停轮、延后结算、大奖、重复点击、余额不足与存档恢复。加 `--screenshots` 可在图形模式保存截图。
