# 物品接口标准

版本：v1，2026-09-30。供商店、库存、图鉴和调酒板块协作对齐。

## 1. 统一入口

| 内容 | 工程内路径 |
| --- | --- |
| 商品定义 | `res://data/supplies/catalog.json` |
| 库存初始模板 | `res://data/supplies/initial_state.json` |
| 成品酒配方 | `res://data/cocktails/catalog.json` |
| 商品读取脚本 | `res://scripts/supply_catalog.gd` |
| 库存脚本 | `res://scripts/supply_inventory.gd` |
| 器具通用脚本 | `res://scripts/supply_tool.gd` |
| 器材与杯型场景 | `res://scenes/supply_assets/` |

路径统一使用 `res://`。这些读取及库存脚本为 `RefCounted` 模块，需要由控制器实例化；当前未加入新的 Autoload。正式游戏应由一个统一控制器持有唯一库存实例，再传给商店和调酒系统。

**本轮准备了资源和可调用的库存接口。正式商店购买、调酒操作判定和总存档连接属于后续接入工作。** 不要在另一个系统重新维护一份库存。

## 3. 商品 JSON 字段

顶层 `schema_version:1`，商品在 `items` 数组，用冰在 `ice` 数组。瓶装示例：

```json
{
  "id": "sku_gin_london_dry",
  "ingredient_id": "gin_london_dry",
  "kind": "ingredient",
  "name": "伦敦干金酒",
  "category": "原酒",
  "contains_alcohol": true,
  "storage_mode": "container",
  "measurement_unit": "ml",
  "quantity_unit": "瓶",
  "package": {
    "purchase_quantity": 1,
    "container_capacity": 750,
    "container_unit": "瓶",
    "source_amount": null,
    "capacity_status": "game_default_unconfirmed"
  },
  "price": null,
  "price_status": "unconfirmed",
  "unlock_policy": "permanent_on_first_purchase",
  "image_path": "res://assets/art/supplies/materials/gin_london_dry.png",
  "texture_resource_path": "res://assets/art/supplies/textures/gin_london_dry.tres"
}
```

| 字段 | 对接规则 |
| --- | --- |
| `id` | 跨模块唯一稳定键 |
| `kind` | 程序区分原料、器材、杯型 |
| `category` | 玩家界面的五类：原酒、配料、装饰品、器材、杯型 |
| `storage_mode` | `container` / `quantity` / `permanent` |
| `measurement_unit` | 原料实际扣除单位：`ml`、`g`、`piece`、`sprig` |
| `package.container_capacity` | 一瓶或一袋满装容量，仅 `container` 使用 |
| `package.purchase_quantity` | 一次买一包时增加多少；瓶装为 1，按件物品可为一包 20 件等 |
| `price`、`abv` | 缺失保持 `null`，不要自行当作 0 |
| `texture_resource_path` | UI / Sprite2D 优先使用的纹理资源 |
| `scene_path` | 器材与杯型可实例化场景 |
| `parts` | 器材独立部件，例如摇壶的三件；部件不是三个可购买商品 |
| `operations` | 后续支持的操作名称，是设计约定，不等于自动完成配方判定 |

来源没给的容量用 `game_default_unconfirmed` 标记。金酒 750ml 等是本轮测试草案；价格、ABV、未确认的单位换算未补造。正式库存存档投入使用后，改变包装容量应使用新 SKU 或迁移旧存档。

## 4. 玩家状态和扣料语义

状态顶层为 `{"schema_version":1,"items":{...}}`，`items` 按商品 ID 存对象。

### 瓶装、袋装

```json
"sku_gin_london_dry": {
  "unlocked": true,
  "quantity": 2,
  "current_remaining": 100
}
```

`quantity` 包含正在使用的这一瓶。其余瓶视为未开启满装。余量使用商品 `measurement_unit`，金酒为 ml，白蔗糖为 g。

容量 750ml 时，上例总可用 850ml；再用 100ml 后，数量变 1，当前余量变 750ml。全部用尽变成数量 0、当前余量 0，但 `unlocked` 永久保留。再次购买不会重置已开启的这一瓶。

### 薄荷叶、装饰品

```json
"sku_lime_wedge": {"unlocked": true, "quantity": 20}
```

只有数量，不存在 `current_remaining`。按整片、整枝、整块、整颗消耗。

### 器材、杯型

```json
"tool_shaker": {"unlocked": true, "owned": true}
```

永久拥有，不按次消耗，也不累计瓶数。首次购买任何商品后都将其 `unlocked` 置为 true；后续消耗不会取消解锁。

## 5. 当前已实现的接口

```gdscript
const SupplyCatalog = preload("res://scripts/supply_catalog.gd")
const SupplyInventory = preload("res://scripts/supply_inventory.gd")

var products = SupplyCatalog.new()
var inventory = SupplyInventory.new()
```

| 模块与方法 | 返回 / 语义 |
| --- | --- |
| `products.get_item(id: String)` | 商品 Dictionary 副本；找不到为 `{}` |
| `products.list_items(category := "")` | 所有商品或指定类别的数组 |
| `products.list_ice()` | 独立用冰数组 |
| `products.get_texture(id: String)` | Texture2D；找不到返回 null |
| `inventory.get_state(id: String)` | 状态 Dictionary 副本；找不到为 `{}` |
| `inventory.is_unlocked(id: String)` | 是否曾经购买解锁 |
| `inventory.total_remaining(id: String)` | 当前与未开启包装合计可用量；原料按 measurement_unit，器具拥有返回 1 |
| `inventory.purchase(id: String, packages := 1)` | bool，记入已完成的购买；本方法不扣金币 |
| `inventory.consume(id: String, amount: float)` | bool，按 measurement_unit 消耗；不足或参数无效则完全不改状态 |
| `inventory.as_recipe_inventory()` | `{sku_id:总余量}` 快照，供现有图鉴 / 配方检查使用 |
| `inventory.serialize()` | 可加入总存档的 Dictionary 副本 |
| `inventory.restore(data)` | bool，校验并恢复；新加入但旧存档缺失的商品初始锁定 |
| `inventory.save_to(path: String)` | bool，显式写入库存 JSON |
| `inventory.load_from(path: String)` | bool，显式读取并恢复 |

失败原因读取 `last_error`。正式购买流程先由商店检查钱包及扣币，再调用 `purchase()`，避免同一购买重复记入。不要直接修改 `get_state()` 返回值，它是副本。

库存不会自动写入当前游戏存档。后续总存档可将 `serialize()` 放入 `supplies` 字段，再由 `restore()` 取出恢复。`initial_state.json` 只作为初始模板，不写入玩家进度。

## 6. 与调酒配方的连接

当前成品酒数据的原料项已有：

```json
{
  "sku_id": "sku_white_rum",
  "amount": 45,
  "unit": "ml",
  "inventory_unit": "ml",
  "inventory_amount": 45,
  "conversion_factor": 1,
  "required": true
}
```

- 实际扣除应使用 `inventory_amount`，它已经表达库存单位下的用量。
- `amount` / `unit` 是配方展示与操作要求，不能直接把 `1 dash` 当成 `1ml`。
- `inventory_amount:null` 表示尚未确认换算，当前曼哈顿苦精即属此情况。实际计量扣除前要先确定商品对应的换算；不要用 0 跳过。
- 可选原料 `required:false` 只有玩家实际加入才消耗，不加入不阻止制作。
- 同一原料多次添加，要按操作累计实际用量；调酒结束或每次添加中选择一个扣料时机，避免同一份用量重复扣除。
- `consume()` 的事务范围是单个商品。整杯同时结算时先汇总并验证全部原料，再统一扣除；失败时不应留下半杯已扣、半杯未扣的状态。
- 现有 `MenuCatalog.inventory` 是旧的总余量字典。后续改为由统一库存生成 `as_recipe_inventory()` 快照，不要再另外维护和消耗它。

## 7. 器具可操作场景

器具用二维独立图片，场景原点在底部中间。摇壶是三个独立 Sprite2D：`Body`、`StrainerTop`、`Cap`。其它器具为独立 `Body`。

| 方法 / 节点 | 用途 |
| --- | --- |
| `drag_to(world_position: Vector2)` | 改变世界位置，拖动控制器自行接鼠标 / 触屏 |
| `set_tilt(degrees: float)` | 设置倾斜角度，以度为单位 |
| `set_open(value: bool, animated := true)` | 三件式摇壶开合盖；其它器具无此动作 |
| `animate_shake()` | 闭盖摇壶的摇和示意；开盖时不执行 |
| `set_fill_ratio(value: float, color := Color("c98537"))` | 可容纳液体的器具显示 0–1 液面；不负责实际毫升或扣料 |
| `get_anchor(name: String)` | 返回 Marker2D 世界坐标；找不到退回器具位置 |
| `HitArea/Shape` | 可供鼠标选中 / 拖动的 Area2D 范围 |
| `Liquid` | 独立液体 Polygon2D，可改颜色与液面，不改空杯 PNG |

锚点：`GrabPoint` 抓取、`RestPoint` 放置、`RimPoint` 杯口、`PourPoint` 倒出口、`FillPoint` 杯内、`GarnishPoint` 装饰；轻压棒、吧勺和滤器另有 `WorkingPoint`。这些坐标是当前图片的原型定位，正式调酒可在场景中微调。

**调酒控制器负责**实际容积、混合配比、拖动输入、器具搭配、制作顺序、计时、倾倒流体、配方评分和扣库存。图片场景提供可摆放部件与视觉接口，不自动生成这些玩法判断。默认液面形状随杯身倾斜，不是物理流体模拟。
