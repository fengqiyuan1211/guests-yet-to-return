# 童年拾忆与手绘酒图接入（2026-10-07）

## 玩家流程

- 背包打开小线给的旧酒单 → 带着酒单去研习；也可进入研发书桌的传说研习台。
- 按配方完美调制后掌握《童年拾忆》，可在营业酒单中选择上架。
- 已经获得旧纸张的存档会自动补上配方获得记录，无须重新打球。材料购买不能绕过剧情奖励。
- 完美出品才显示金色“传说 · 未完待续”；仅区分稀有度，暂不加分。总评分仍以现有规则计算且不超过100。
- 配方：白朗姆酒35ml、马拉斯奇诺樱桃利口酒10ml、青柠汁15ml、可乐90ml、鸡尾酒樱桃1颗。高球杯、标准方冰100g。加料后轻搅3—6秒，最后装饰；不摇和。
- 四项属性由现有感官模型计算，约为酒感36.73、甜56.15、酸47.47、苦10.91，均不是百分比。冰不计原料库存。

## 出图与保存

DIY结果页点击“命名并保存配方”，进入酒名、故事、笔记和生成图片界面。只有图片回传并确认后才正式加入成品配方库；未出图的原杯仍作为工作台试调记录保留。传说完美结果页有“生成手绘酒图”，保存后成为该传说酒的封面。

并非每次营业送酒都出图。已有配方日常复做不重复调用模型，也不等待绘图后才收款。

入口：scripts/research_image_dialog.gd；实际成品转请求：scripts/research_image_request.gd；HTTP传输：scripts/diy_image_client.gd。

输入来自成品杯实际余量、杯型、留下的冰和装饰，不使用目标配方覆盖实际用量。不附粗糙预览时仍会按实际配方生成，服务的可选参考预览接口保留。用户故事只影响插画氛围。

图片保存在 user://diy_cocktails/images/。配方与图片路径一起存入库存存档的 workbench.research：DIY为 recipes[id].image_path/image_generation，传说封面为 legendary_images[id]。实际成品数值、消耗和评分不交给模型计算。

出图表单和任务缓存位于 user://diy_cocktails/drafts/。网络中断后重试复用请求编号；重开已下载的图可以继续确认，不再次生成。明确点击重新生成或原服务任务已失败后重试，才新建付费任务。关闭界面会停止客户端等待，服务端已接受的任务仍可能继续完成。

## 服务配置

先启动 services/cocktail-image-service/run.py，再在游戏中出图。本机默认 http://127.0.0.1:8787。

游戏内地址在 data/diy_image_service.json；可用 user://diy_image_service.cfg 的 [service] 下 url、token 字段做本机覆盖。token 是自建服务访问凭据，不是千问密钥。模型密钥仍只填写在 services/cocktail-image-service/.env，勿提交 Git。

风格更新为钢笔淡彩、彩铅手绘，细墨线、留白、克制高光；无文字、无纸底，回传透明PNG。few-shot已换成游戏现用五款手绘图，路径及哈希登记在服务config中。style_id保留接口兼容，prompt_version为diy-cocktail-handdrawn-v4。改风格后需重启服务。

## 数据入口

- data/research.json：唯一传说配方定义，稳定ID childhood_keepsake。
- data/minigames/story_items.json：旧道具 item_recipe_after_school 链接配方与 buff.to_be_continued。
- data/guest_mechanics/buffs.json：传说Buff定义，effect_status=reserved；没有配置加成。
- scripts/research_data.gd：从有效正式获胜记录和道具拥有状态补齐acquired。
- scripts/supplies.gd：首次完美mastered后同步营业菜单解锁。

## 测试范围与限制

已用独立测试存档验证获得门槛、旧道具迁移、实际加料搅拌到完美、库存与掌握保存、上架、普通/传说隔离、DIY冒用无效、传说加分为零，以及本地HTTP提交/轮询/下载/重开/确认保存链路。网络链路使用模拟图片，不代表已验证千问当前密钥或某一张真实生成图。真实图片仍需玩家检查杯型、颜色和装饰。

本轮未接入DIY营业上架（原研发版也尚未开放）；DIY成品可在研发配方库与图鉴中查看。本次已接通的是《童年拾忆》的营业上架。
