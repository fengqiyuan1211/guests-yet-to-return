# 原料与器具素材接入标准

适用于《致未归的客人》当前 Godot 4 工程。此包准备原料图片、器具部件、商品资料和库存模型。正式商店结账和调酒配方消耗在后续使用这些接口接入。

## 1. 本次范围

| 类别 | 数量 | 内容 |
| --- | ---: | --- |
| 原酒 | 10 | 金酒、绿查特酒、樱桃利口酒、白朗姆、伏特加、龙舌兰、君度、黑麦威士忌、甜红味美思、苦精 |
| 配料 | 8 | 青柠汁、柠檬汁、糖浆、苏打水、汤力水、可乐、白蔗糖、薄荷叶 |
| 装饰品 | 4 | 薄荷枝、青柠角、柠檬片、鸡尾酒樱桃 |
| 器材 | 6 | 三件式摇壶、量酒器、滤器、轻压棒、吧勺、调酒杯 |
| 杯型 | 4 | 鸡尾酒杯、高球杯、球形杯、碟形杯 |

32 个物品定义，共 36 张透明 PNG：22 张原料与装饰、12 张器具部件与杯型、2 张额外的用冰素材。当前商店售卖 28 件，4 种杯型默认拥有。摇壶为一个商品、三个可独立操作的部件。备料用的刀、砧板、榨汁器不在此包中。

含酒精的利口酒、加强葡萄酒和苦精均归入「原酒」。`source_category` 保留工作簿原分类，配方中的用途字段仍可表示基酒或配料。鸡尾酒樱桃的含酒状态在原表为待核，因此保留 `contains_alcohol: null`，目前作为装饰；后续选定实际商品若含酒，应将类别改为原酒，其按颗计数的库存方式可以保留。

冰仅作为制作素材，放在独立 `ice` 数组，既不进入原料购买、解锁，也不进入原料库存。

图片是保留原始像素的透明 RGBA PNG，Godot 可以直接导入。统一路径使用 `res://`，不依赖某台电脑的绝对路径。优先在 UI 的 `TextureRect` 和场景的 `Sprite2D` 上使用 `.tres`，避免透明留白造成显示大小不一致。原 PNG 并未被裁切或修改；区域是 AtlasTexture 的显示设置。

本批使用内置 ImageGen 生成，当前为 `saloon-supplies-matte-v2` 柔和西部手绘风。原酒参考现实产品的不同瓶型，后续以本批蓝色方瓶金酒作为绘画风格参考，保持完整主体、透明背景、细褐色轮廓与柔和色面。避免亮金边、强白反光和镜面条纹。瓶签可用通用酒种短标记或简化植物图案，中文商品名由游戏 UI 排版。完整瓶型来源和可复用模板见《原酒瓶型与柔和手绘素材-v2》。

## 3. 商品资料和玩家状态分开

`catalog.json` 记录这个物品是什么；玩家是否买过、还有多少放在库存状态中。不要把玩家购买结果写回商品定义，也不要改初始模板来保存进度。

稳定 ID 沿用当前配方的 `sku_id`，例如 `sku_gin_london_dry`。器材使用 `tool_shaker` 等 ID，杯型使用 `glass_highball_glass` 等 ID。

原表已给的包装数量和演示金币价格保留原值。原表没有给容量的商品，本包为了测试补货采用明确标记的游戏草案容量：`package.capacity_status="game_default_unconfirmed"`，同时 `source_amount=null`。这不是现实商品的容量保证，可在正式商店接入前统一调整。缺失的价格与 ABV 保持 `null`，曼哈顿苦精的 dash 换算仍不自行估算。

## 4. 三种库存方式

### 瓶装或袋装 `container`

```json
{
  "unlocked": true,
  "quantity": 2,
  "current_remaining": 100
}
```

- `quantity` 包括正在使用的这一瓶。
- `current_remaining` 只记录当前瓶剩余的毫升，不是所有瓶的总量。
- 其余瓶视为未开启，容量来自商品的 `package.container_capacity`。
- 上例若瓶容量 750ml，总库存为 850ml。再消耗 100ml 后变为 `quantity:1, current_remaining:750`。
- 全部用完变为 `quantity:0, current_remaining:0`，`unlocked` 仍为 `true`。
- 补货不会重置已经打开的这瓶的余量。
- 白蔗糖同样按袋与克数记录，包装单位为袋，余量单位为克。

### 按件 `quantity`

```json
{"unlocked": true, "quantity": 20}
```

薄荷叶及全部装饰品只有数量，没有 `current_remaining`。数量单位由商品资料提供，分别为片、枝、块或颗。一次购买增加 `package.purchase_quantity` 件，消耗必须为整件。

### 永久拥有 `permanent`

```json
{"unlocked": true, "owned": true}
```

六种调酒器材和四种杯型默认拥有，不计剩余量、不售卖，恢复旧存档时也自动补齐并保存。商店只显示原酒、配料和装饰品。

## 5. 使用库存接口

```gdscript
const Inventory = preload("res://scripts/supply_inventory.gd")
var stock = Inventory.new()

# 金币结算成功后，由商店调用；此方法本身不扣金币。
stock.purchase("sku_gin_london_dry", 2)
stock.consume("sku_gin_london_dry", 650.0)
print(stock.get_state("sku_gin_london_dry"))
# unlocked=true, quantity=2, current_remaining=100

stock.consume("sku_gin_london_dry", 100.0)
# quantity=1, current_remaining=750

stock.purchase("sku_lime_wedge", 1)
stock.consume("sku_lime_wedge", 1)
print(stock.get_state("tool_shaker")) # 默认 unlocked=true, owned=true
stock.save_to("user://supply_inventory.json")
```

`consume()` 先检查整次用量，余量不足时返回 `false`，状态完全不变。正式调酒系统应先验证全部原料充足，再结算整杯的多项消耗；本包单项消耗接口不是整杯多原料事务。

`serialize()` / `restore()` 提供可写入总游戏存档的结构。`restore()` 会拒绝负数、非整数件数和不合理余量，并为旧存档缺少的新商品建立未解锁状态。`get_state()` 和查询资料返回副本。

正式游戏已使用唯一 `Supplies` Autoload 管理库存、交易与保存，`MenuCatalog.inventory` 只接收其总余量快照。调酒调用 `Supplies.consume_many()`，不要另建库存或重复扣料。图鉴配方无需改变 SKU；器材和杯型的默认拥有规则由恢复流程兼容旧存档。完整共用方法见《物品接口标准.md》v1.2。酒谱点亮永久保留，配方材料是否够调一杯仍按当前库存检查。

## 6. 器材场景和操作

所有器材与杯型场景的原点设在底部中间，便于摆到吧台、旋转和拖动。场景包含独立 Sprite2D、HitArea 和 Marker2D。摇壶的 `Body`、`StrainerTop`、`Cap` 分开；其它器材为一个完整主体。

```gdscript
var shaker = load("res://scenes/supply_assets/shaker.tscn").instantiate()
add_child(shaker)
shaker.drag_to(Vector2(600, 600))
shaker.set_open(true)       # 杯盖移开
shaker.set_open(false)      # 合盖
shaker.animate_shake()
shaker.set_tilt(-45.0)
var pour_at: Vector2 = shaker.get_anchor("PourPoint")

var glass = load("res://scenes/supply_assets/highball_glass.tscn").instantiate()
add_child(glass)
glass.set_fill_ratio(0.65, Color("c98537"))
```

锚点包括 `GrabPoint`、`RestPoint`、`RimPoint`、`PourPoint`、`FillPoint`、`GarnishPoint`，部分手持器材另有 `WorkingPoint`。液面使用独立 Polygon2D，不把固定酒液画死在空杯 PNG 中。

这些是供后续操作接入的二维素材与原型接口。`set_fill_ratio()` 展示液量比例；准确的毫升、混合颜色、流体、碰撞、倒酒粒子和配方判定由后续调酒控制器管理。锚点与液体范围可在场景里继续细调，不需要重新生成图片。

## 7. 预览与验收

在 Godot 打开 `scenes/supply_assets/asset_gallery.tscn`，使用「运行当前场景」查看三组图片。点击器材或杯型会打开操作示例，摇壶可开合和摇动，空杯可加入液体及倾斜。这是独立素材检查场景，不占用主页入口。

- `tests/verify_supply_inventory.tscn` 检查库存规则、保存恢复和配方 SKU。
- `tests/verify_supply_assets.tscn` 检查全部纹理、透明背景、场景部件和操作接口。
- 本次预览图保存在工作区的 `output/supply-assets-preview/`。

后续增加商品时，添加一个稳定 ID、一张同风格透明图、对应纹理资源与初始状态。器材增加独立场景。修改同一包装的容量会改变未开瓶库存解释，正式存档投入使用后，应通过新 SKU 或存档迁移处理容量变化。
