# 港口商店接入与验收

更新：2026-10-01。当前商店为可以实际购买、补货和保存的 Godot 界面。

## 进入与操作

运行工程主场景，在酒馆左侧选择商店，进入「港口货栈」。白发商人和船港为独立场景，不进入酒馆客人池。

- 原酒、配料、装饰品三类，共 22 件商品，每页最多六件。
- 点击瓶身或价格签选中商品；底部购买单分开显示名称、包装规格、库存和当前包装余量。
- 用加减号调整要买的包装数，点击购买。装饰品按每包包含的件数入库。
- 上一页、下一页在货架下方的牛皮纸条上；到页首、页尾时相应按钮禁用。
- 换页有 0.32 秒滑移淡化，期间不能选货或购买；分类切换会取消旧动画并回到第一页。
- 点「回酒馆」或按 Esc 返回。重新进入读取实际库存和金币。

调酒器材六种、杯型四种默认拥有，不在商店展示和收费。旧进度首次载入时会自动补齐，保留材料数量和开瓶余量。它们的资料、图片和可操作场景仍保留，供调酒板块使用。

## 港口随时间变化

港口与酒馆共用游戏时钟，现实 1 秒等于游戏 1 分钟。四张画面在下列时段连续变化，进入、返回或提前营业加速时保持同步。白天、黄昏与黎明使用自然光，夜晚点亮既有灯具。

| 游戏时间 | 港口画面 |
| --- | --- |
| 21:00–次日 04:00 | 深蓝夜空、暗色海面、暖色港灯 |
| 04:00–05:30 | 夜晚逐渐过渡到黎明 |
| 05:30–06:30 | 清冷晨光与银蓝海面 |
| 06:30–08:00 | 黎明逐渐过渡到白天 |
| 08:00–16:00 | 自然日光与蓝色海面 |
| 16:00–18:00 | 日光逐渐转为夕照 |
| 18:00–19:00 | 暖色黄昏 |
| 19:00–21:00 | 黄昏逐渐入夜、灯光渐亮 |

场景读取 `TimeManager.visual_minutes()`，包括整数分钟之间的时间、暂停状态和提前营业的加速进度。背景与柜台共享混合材质与完整画面的纹理坐标；人物与物品图单独调整光色，不影响纸张、标签或控件。图片尺寸可以不同，但宽高比及构图必须一致。更换时段图时，以当前白天图作编辑参考，保持货架和柜台位置。

四张图片在 `assets/art/shop/harbor-shop-{day,dusk,night,dawn}.png`；完整生成提示词与来源在同目录的 `day-cycle-prompts.json`。专用验收场景为 `tests/verify_harbor_day_cycle.tscn`，覆盖时钟、平滑边界、柜台坐标、光色、商人点击和重返商店；使用 `--screenshots` 时保存运行画面到工作区 `output/harbor-time-preview/`。

本轮验收：无窗口运行 326 项通过；实际图形运行 333 项通过，包含七张截图。四张时段及 19:45、04:45 混合画面均已检查，未见明显柜台接缝或背景重影。测试使用独立临时进度。

## 玩家存档如何变化

物品定义在 `data/supplies/catalog.json`，初始模板在 `initial_state.json`。这两份工程数据不会随着购买改变。

玩家库存保存在 `user://supplies_state.json` 的 `inventory.items` 中。例如金酒容量 750 ml，已有一瓶且当前剩 100 ml：

```json
"sku_gin_london_dry": {
  "unlocked": true,
  "quantity": 1,
  "current_remaining": 100
}
```

再买一瓶后 `quantity` 变为 2，`current_remaining` 仍为 100；下一瓶视为未开封，合计可用 850 ml。用完当前 100 ml 后，`quantity` 变回 1，`current_remaining` 变为 750。`quantity` 包含正在使用的包装。

金币仍由 `SlotWallet` 保存至 `user://wallet.json`。库存交易使用持久购买意图和幂等钱包收据，处理中断会恢复，不重复扣币或发货。不会因升级本版清空玩家进度。

## 图鉴和调酒同步

`Supplies` 是商店、调酒和图鉴共用的唯一正式库存服务。成功购买或实际扣料后，将实际总余量同步到 `MenuCatalog.inventory`，通知图鉴更新。

两种判断分别处理：

| 判断 | 规则 |
| --- | --- |
| 酒谱点亮 | 必需材料及必需装饰首次购齐后永久点亮；冰和可选装饰不参与，器具默认满足 |
| 当前材料是否够用 | 用实际剩余总量与配方用量比较；点亮后缺料仍需补货 |

`Supplies.missing_recipe_requirements()` 用于永久点亮条件；`MenuCatalog.ingredient_available()` / `ingredient_progress()` 用于图鉴当前材料进度。调酒控制器汇总真实加入量后调用 `Supplies.consume_many()`，避免重复扣料。苦精 dash 的毫升换算仍待确认，不自动当作 1 ml。

未点亮酒卡现在不能打开详情，悬停只列出尚缺的必需物品；买齐点亮后开放。点亮后的详情会区分缺货、已用完和余量不足。图鉴翻页期间收到库存变化，动画结束后会补刷新。

协作方法、稳定 SKU、器具场景与消耗单位详见《物品接口标准.md》v1.2。

## 相关文件

| 文件 | 用途 |
| --- | --- |
| `scenes/harbor_shop.tscn` / `scripts/harbor_shop.gd` | 港口场景与可交互货架 |
| `assets/art/shop/` | 空货架船港背景、透明商人 |
| `scripts/supplies.gd` | 统一库存、购买、扣料、保存与图鉴桥接 |
| `scripts/supply_inventory.gd` | 包装余量、件数与默认器具模型 |
| `data/supplies/shop_prices.json` | 22 件商品试用价格，标记 game_provisional |
| `tests/verify_harbor_shop_ui.tscn` | 原生鼠标点击、动画锁、购买、图鉴/酒单同步与窗口布局验收 |
| `tests/verify_supplies_shop.tscn` | 扣币、保存、中断恢复、旧档迁移与酒谱点亮验收 |
| `tests/verify_supply_inventory.tscn` | 包装跨瓶、按件消耗与恢复验收 |
| `tests/verify_codex_lock_hover.tscn` | 锁卡原生悬停提示、点击/直接调用禁入、购买后缺项更新与解锁 |

测试必须为五个存档服务都指定独立 `/tmp` 路径，禁止对真实玩家存档运行验收。生产运行由 Godot 自动导入 PNG 和资源，不需要把 `.godot` 缓存提交给朋友。
