# 艾达转速与米洛失败演出修复

2026-10-09。

## 艾达

原摆轮角度使用 `time * sin(time * 7)`。外层累计时间会让振幅和瞬时角速度随游玩时长增长，因此越玩越快。原齿轮重新连通时又直接采用累计时间角度，可能瞬间跳到另一朝向。

现在新增 `scripts/watch_repair_motion.gd` 管理各齿轮和目标的独立动画相位：普通齿轮和秒针轴保持固定角速度；摆轮固定振幅 0.55 弧度，摆动相位按固定频率推进。所有相位限定在一周内。断开时停在原角度，接通后从这里继续；切关／重玩重置视觉相位；暂停不推进，长帧只做有限的视觉补进。

这一层只改变表现，不改连接判定、解锁、存档结构或奖励。10 分钟模拟、30/144 帧比较、断开接回、长帧及重玩共 8 项专项检查通过。

## 米洛

可载人的错误安排现在允许船先离岸，约 0.85 秒航行动画后展示全屏失败插画，再显示具体失败原因。例如第一趟带走一名巡路员，提示此岸将剩下 2 名巡路员、3 名修路工。

按空格／点击“重试这一趟”回到出发前的稳定局面，可以重新选人；也可返回手帐。正确完成过的航次仍保留。失败不收金币、不耗库存、不改变故事、不能触发首通奖励。空船和超过两人的装载仍属于无法执行的物理输入，不进入失败演出。

失败演出是对错误方案的表现，不把违反安全约束的两岸人数写进存档。底层 `crossing_failure` 返回失败岸、人数和文案；正式有效航次仍由原 `cross` 命令原子提交。航行中暂停、失败后重复按键、退出与重试都不能重复移动人物。

新增美术 `assets/activities/v2/milo-failure.png`：暖色木头沙盘中散乱的木偶、绳与地图，表达这一轮安排失败。不是历史人物死亡，也不是强制重开整局。

完整角色流程 271 项、跨进程恢复 9 项检查通过，其中增加了失败开船、精确人数、暂停、CG 打开和空格重试的实机输入测试。测试仍使用独立临时存档。退出时原有资源清理警告仍存在，未在本次扩大范围处理。
