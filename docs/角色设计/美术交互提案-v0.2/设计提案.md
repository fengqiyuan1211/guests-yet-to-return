# 三位客人的美术与交互提案 v0.2

2026-10-09｜**待选择的设计方案，本轮未修改游戏代码、音频资源或运行配置。**

本稿与《角色小游戏首版-实现与试玩说明》分开：上一份描述已实现内容，本稿描述建议改动。图是视觉概念，声音是制作说明，并非已经可以播放的新增素材；尺寸、时长、容错与难度都需要实机验证。

## 1. 共同方向：让玩家摆弄桌上的东西

保持现有酒馆的暖色手绘、木头、黄铜、羊皮纸、港口灯火。主玩法占画面大部分，规则收进短纸条；人物只留小头像和适时一句反应，不再占掉一整列。

三人有不同的触感主题：

| 角色 | 场景 | 触感关键词 |
| --- | --- | --- |
| 米洛 | 木头渡河沙盘 | 拿起木偶、落座吃重、水波、绳索 |
| 老霍克 | 桌上三层灯光影戏 | 提灯卡位、柔光、影子、脚步与木门 |
| 艾达 | 绿毡修表台上的机芯 | 金属组件落槽、齿轮咬合、上弦、恢复滴答 |

交互共识：

- 按下就让物体响应，拖动位置紧跟鼠标；弹性和滞后只用于影子、挂件与落位收尾。
- 可放的位置出现贴合物件形状的落点预览。无效松手回到原处，给出具体原因。
- 常用动作由拖动、空格与少量快捷键完成，不在每次落位后再弹确认框。
- 不给所有按钮加说明弹窗。只对陌生规则、首遇操作提供短提示，平时用底部纸条更新下一步。
- 缩小画面后仍能看清人物种类、船位、灯位和齿轮接点；身份通过形状／徽记区分，不只靠颜色。
- 特效不挡住输入区域。关键声音和视觉提示配对，关闭声音也能完成。
- 提示、慢速与撤回不扣首通故事奖励。暂停、返回手帐和恢复原酒馆时间的行为保留。

## 2. 米洛：保留渡河规则，做出摆沙盘的感觉

界面图：[米洛渡河界面](01-米洛-渡河界面.png)

声画说明：[米洛交互、特效与音效](02-米洛-声画说明.png)

主画面是真实材质感的桌面河流沙盘，两岸有码头、围栏和可站立区域。六枚木偶有厚度、底座和接触阴影；蓝衣星徽是巡路员，棕衣铲形徽记是在押修路工。两席小船是直接操作的物件。

预览图显示：左岸 5 人、船上 1 人、右岸 0 人，共六人。计数必须分清“岸边”与“船上”，开船前校验出发后两岸状态，不因概念图排版混淆规则。

| 动作 | 可见反馈 | 声音意图 | 建议节奏 |
| --- | --- | --- | --- |
| 拿起木偶 | 底座离桌、影子变软；物件立即跟手 | 干木轻碰，不播放通用按钮音 | 当帧响应 |
| 拖近空船位 | 对应座位出现淡色落点，满船时不吸附 | 不循环播放悬停音 | 即时 |
| 松手上船 | 木偶落定，船略向该侧倾斜，然后回稳；小水纹散开 | 木底落船＋轻水声 | 约 0.2 秒 |
| 空格开船 | 船缓起、平稳渡河、轻靠岸；尾流和绳索跟随 | 船板吱响、绳摩擦、水流；靠岸单独轻碰 | 约 0.8 秒 |
| 暂不能开船 | 船仍留在码头；危险一岸旁出现短句，如“这一岸巡路员太少” | 一次低木音，不用尖锐警报 | 约 0.15 秒 |
| 撤回 | 恢复上一步位置和计数，短动画过渡 | 很轻的木件回摆 | 不重播整段渡河 |
| 完成 | 六人站稳在驿站，地图上一条归途被描清 | 最后一声靠岸＋短而温暖的收尾乐句 | 可直接返回或重玩 |

保留经典安全规则、两席小船、撤回与提示。水的体积感由遮罩、反光、波纹和尾流营造，首轮不增加复杂流体模拟。提示只建议下一趟，不抢走玩家的控制权。

## 3. 老霍克：让“把灯送过去”成为主要动作

界面图：[老霍克影戏界面](03-老霍克-影戏界面.png)

声画说明：[老霍克交互、特效与音效](04-老霍克-声画说明.png)

保留三路接应、六位旅人，但改为木框、纸山、人物剪影和一盏能移位的黄铜灯。道路、等候处和货棚门口都有明确位置，背景风沙只是轻层次，不盖住来客。

灯位操作建议改为“按住灯拖动／点选道路／方向键”。鼠标普通经过场景不自动切灯，避免去点菜单时误操作。拖动跨越灯位边界时加一个小缓冲范围，减少指针抖动造成反复跳位；键盘和点击直接选到目标位置。

| 动作 | 可见反馈 | 声音意图 |
| --- | --- | --- |
| 拿起、移灯 | 提环响应，灯罩短摆；轨道目标槽清楚 | 黄铜轻碰＋很低的轨道摩擦 |
| 到位 | 灯座稳稳卡住，光斑落到道路；余摆不延迟操作判定 | 单次柔和卡位声 |
| 旅人求助 | 招手与布旗同时提示，剪影保持清楚 | 短招呼／布旗拍动，次数受限 |
| 持续照稳 | 暖光形成完整可走区域，细弧提示接应进度，影子随光改变 | 灯罩、细微燃烧声；风声让位 |
| 接回 | 人物真正走过亮处、进门，随后人数加一 | 脚步、门轴、小而短的确认铃 |
| 错过 | 留在安全棚下，再次示意，不坠落、不扣掉已接回的人 | 低声提醒，不用惊吓音 |
| 全部接回 | 货棚灯逐盏亮起，三个名字留在舞台底座 | 风声减弱、门内人声、温暖和弦 |

建议起点：卡位收尾约 0.15 秒；照稳约 0.6 秒；进门约 0.5 秒。动画、逻辑和计数必须对应：同一个旅人不能因为光反复扫过而被重复接回。

增加变化时先用“提前招手、不同的接近速度、前后错开的请求”。前两人只教操作，中间才出现需要判断的先后关系；不要靠同时堆满三路制造忙乱。慢速辅助保留。小游戏仍是共同回忆的影戏，不用失败改写角色故事中的生死。

## 4. 艾达：为什么建议更换核心玩法

现版是看／听一段顺序，再重复它。问题在于玩家不知道自己的输入修复了哪处故障，几轮体验相似；开启顺序提示后，也容易只剩照着按。

这次建议保留“终于有时间修自己的怀表”的故事，换成**能试、能观察、能调整的机芯连通拼图**。完成反馈来自机械重新运动，而不是只出现一个过关标记。

### 4.1 可参考的经典原型

以下原型描述来自官方或作者资料，适配和取舍是本项目的设计判断。

| 原型 | 原有核心 | 如何改成艾达的玩法 | 取舍 |
| --- | --- | --- | --- |
| [Net／NetWalk 类](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/js/net.html) | 旋转方格，接成完整网络；已连接部分提供可见反馈 | **A：机芯复位，推荐。** 转动和装入齿轮组件，让发条带动两个目标部件 | 易懂、有空间推理、能直接看到修复进展；需要认真设计接点和少量关卡 |
| [Rush Hour](https://legacy.thinkfun.com/wp-content/uploads/2017/02/RushHDeluxe-5050-IN.pdf) | 沿各自方向移动障碍物，为目标车腾出出口 | **B：卡件解围。** 滑动压板与长短组件，为受损机芯打开取出通路 | 拖动反馈强、规则成熟；体验偏拆件和解堵，修好怀表的联系稍弱 |
| [Rhythm Heaven／节奏天国](https://iwataasks.nintendo.com/interviews/wii/rhythmheavenfever/0/0/) | 用少量按键配合节拍的短小游戏 | **C：走时校准。** 根据可见摆轮与滴答声按空格，逐渐让走时稳定 | 声画手感突出；容易又变成按键测试，推荐只做可选短收尾 |
| [The Incredible Machine／Contraption Maker 系](https://spotkin.itch.io/contraption-maker) | 用给定部件组装装置、触发连锁反应并达到目标 | 借用“装好一部分就看见一部分运转”的反馈；不照搬完整物理沙盒 | 自由度大，也更难控制制作范围；适合作为 A 的表现参考 |

Net 原本要求整个网络相连且无闭环；本项目不直接照搬全部目标，建议采用固定的发条源、指定目标与限定组件，以让“修这一块表”更明确。只参考规则和反馈，不使用原作关卡、画面、声音。

### 4.2 推荐 A：《慢半拍的下午 · 机芯复位》

概念图：[艾达机芯复位](05-艾达-机芯复位.png)

本图主要用于选择机芯玩法和桌面材质；人物小像为生成占位，实装继续使用现有艾达立绘。正式界面会与另外两人统一，始终保留暂停和返回手帐。

第一视角俯看绿毡修表台。怀表打开，旁边只有零件盘、镊子和简短笔记。机芯是放大、简化的可读拼图，不宣称模拟真实制表工程。

**目标：用有限组件，把发条的动力接到秒针轴与摆轮。**

- 发条是固定起点，两个目标有各自形状标记。
- 可操作件是带有齿轮、桥板和边缘接口的“组件座”，有直通、转角、分支等类型。转的是整个组件座；不是把普通圆齿轮转九十度就能改变连接。
- 拖动组件到空槽；选中或拿着组件时按空格旋转九十度；松手安装；Z 撤回。提示始终写当前空格会做什么。
- 接点方向吻合、通到发条的部分开始慢慢转动。断点后的部件保持静止，让玩家直接看出卡在哪里。
- 正确放入只说明位置可用，不等于整题已解；不会把完整解法用绿色一路标出来。
- 两个目标都接通后，发条、摆轮和秒针形成稳定连续动作，再进入上弦收尾。

建议三小局，而非越拖越长的一道题：

| 段落 | 新东西 | 目标体验 |
| --- | --- | --- |
| 1：让它先动起来 | 3×3、小量可转动件、单目标 | 第一次接通就看到传动往前走 |
| 2：给旧零件换个位置 | 从零件盘选有限组件；有固定不能移动的位置 | 选择与空间安排，减少无脑点旋转 |
| 3：把时间接回来 | 稍大的盘面、两个目标、需要分支 | 看懂整条链，完成后连续走时 |

建议一次约 2–4 分钟，无倒计时，不按手速给故事奖励。题目先人工制作、自动检查可解，再少量增加变体；不直接开放无限随机。卡住时先指出一处断点，第二次才提示下一步。

完成后的“上弦”优先做成短而有触感的拖转表冠动作，空格也可替代；**不再追加必须通过的节奏关**。如果你更喜欢音游，方案 C 可作为重玩挑战，但不与 A 同时强制塞进首通。

### 4.3 艾达的声音、特效与人物收尾

| 事件 | 反馈 |
| --- | --- |
| 拿起组件 | 金属轻触毡垫，出现小而软的离桌影子 |
| 旋转 | 组件座清楚转到下一档，短棘轮声；不能只闪一下边框 |
| 落槽 | 轻“咔嗒”与贴合阴影；错位则回原处，给出具体接点方向 |
| 动力接通 | 相邻齿轮依次开始运动，机械运转声逐步加入；不画魔法电流 |
| 接到摆轮 | 摆轮来回振动，第一次出现清楚的滴答 |
| 完成 | 秒针稳定走动，声音由断续变均匀，艾达把原本看向门口的注意力留在表上 |

剧情收尾建议：“还快一点。没关系，今天有时间再调。”仍给她留下继续学习和修整的空间。玩法简化和技术拟真度需统一，首版不算真实齿比、惯性、摩擦和擒纵力学。

## 5. 声音整体如何做得舒服

- 三人各有材质主角：米洛以木与水为主，霍克以金属、风与脚步为主，艾达以细小金属和机芯为主。
- 同类关键落点准备 3–5 个轻微不同的样本，避开每次都同一个“叮”。木偶落桌与落船也应区分。
- 拖动摩擦跟随移动量与速度，静止不循环响；快速重复操作合并短时间内的同类音，避免叠成噪音。
- 操作声优先，环境层轻。背景乐沿用大厅的温暖西部／港口语汇，可用同一主题的小变奏；霍克低风声，艾达稀疏拨弦与滴答，不做阴森持续低音。
- 声音确认跟真实状态提交一致：没成功落位就不响成功音，未接到人就不播放进门声。
- 各声部独立控制音量。灯光提示、木偶落点、机芯运动都可在静音下读懂。
- 真正的音频素材选择、制作和试听放在你确认方向后的实现阶段。本轮的声画图只说明声音类型及触发点。

## 6. 确认后如何落地与验收

先统一可操作物的拿起、拖动、有效落点、无效返回和音效触发，再逐个替换场景画面。米洛先做单枚木偶＋一条船的完整操作链；霍克先做一盏灯＋一个旅人的完整接应链；艾达先做一关完整连通题，通过后再扩充关卡。

保持原有手帐、正式邀请、首通奖励、库存与酒馆时间接口。艾达更换玩法时保留已得的正式解锁和奖励记录；旧的未完成记忆局用明确提示转入新玩法，不按新规则误读旧记录，也不重复发奖。

手感验收重点：

1. 拖动对象没有故意跟手延迟，落位范围足够，连续操作不会掉输入。
2. 船载人数、岸边人数、灯位与进度，画面和逻辑始终一致。
3. 动画播完、快速重按、暂停恢复，都不会重复移动、重复接人或重复领奖。
4. 不用声音也能看懂每个关键信号；无需打开一串小窗才能完成。
5. 缩小窗口、降低特效、静音和较低帧率下仍可操作；用实际试玩再调整参数，概念图不能代替这一步。

## 7. 交付文件与生成方式

本目录有三张界面概念 PNG、两张声画说明 PNG。两张说明图另附同名 HTML，可编辑文字、时长和矢量示意；它们是动作设计图，最终美术以界面概念为准。

界面图使用内置 imagegen 生成，声画说明图用 HTML／SVG 排版后导出；未使用 API／CLI 图像生成。完整生成提示词和来源见 [生成记录.json](生成记录.json)。此前的实机截图与旧概念图均保留，没有覆盖。
