# 角色小游戏 v0.2：机芯复位与声画交互

2026-10-09。此文记录已实现内容；视觉方向来自《美术交互提案-v0.2》，本轮采用艾达方案 A。

## 如何进入与操作

入口仍是 **手帐 → 角色 → 专属小游戏 → 开始游戏**。测试阶段三位角色均提供演示入口；演示不消耗原料、金币，不推进剧情或发放正式奖励。

| 角色 | 操作 | 完成条件 |
| --- | --- | --- |
| 米洛 | 拖动或点击木偶上船；点击船上木偶或拖回当前岸边下船；空格开船；Z／右键撤回；H 提示 | 六人都抵达对岸；每船 1–2 人，有巡路员的岸边，巡路员不得少于修路工 |
| 老霍克 | 拖动提灯、点击道路、↑↓／W S 切换灯位；可开启慢速辅助 | 接回六人；照稳约 0.6 秒，旅人再走约 0.55 秒进门，随后增加人数 |
| 艾达 | 拖动组件到空槽或右侧零件盘；点击选中或拖着时空格旋转；Z／右键撤回；H 提示；R 重置本段 | 三段拼图都接通；最终接到秒针与摆轮后拖表冠或按四次空格上弦 |

三款都有暂停、返回手帐。离开窗口会暂停并停止局部操作声。开启辅助、提示和撤回不会扣故事首通奖励。

艾达空格的用途会随上下文变化：拖着组件时始终旋转；没有拖着组件且本段已接通时进入下一段／上弦；其他情况旋转已选组件。不能把组件覆盖到已有组件的槽中，先把原件放回盘里。旋转与移动是两个独立可撤回动作。无效落点会保留组件，不消耗任何材料。

## 这一版实际改变了什么

### 共同页面

- 场景成为主要操作区，保留小头像、上方标题与进度、底部浅色提示条。
- 使用项目原有角色立绘，不采用概念图生成的人物替身。
- 静态美术与活动物件拆层：背景不烘焙可移动木偶、船、提灯或拼图组件。
- 交互命中区与动画分开，装入、旋转、接人、领奖只有成功提交逻辑后才确认。
- 新图使用缩小时的 mipmap 过滤，减轻细小金属纹理闪烁。

### 米洛：渡河沙盘

新河岸背景、巡路员与修路工木偶、小船，均为本轮制作的独立资源。船有两个位置提示，拿起时显示木偶拖动预览。落位伴随吃水起伏；渡河使用约 0.85 秒缓入缓出，配合波纹与靠岸声。

岸边人数与船上人数分别显示，航行中画面保留船上乘客，不提前把他们画到对岸。渡河安全规则与最短路径提示沿用原有纯逻辑验证。航行中不能再开船或改变乘客。最后一趟靠岸后才打开完成窗。

本版回到手帐保存的是已确认的渡河步骤；尚未开船的临时选人不会写入正式航行记录。返回时可重新选人，没有资源损失。

### 老霍克：灯光影戏

三层木框与纸山背景、一根黄铜轨道、一盏可移动灯、三个灯位。普通鼠标经过不再切换灯位；拖动跨过位置边界时有小幅缓冲，减少来回抖动。灯位逻辑立即改变，灯具短暂滑动与余摆负责表现。

旅人有招手剪影、布旗和接应进度弧。照稳后进入 `walking` 阶段；这个阶段即使移动灯，也会让已经接应的旅人走完，进门才写入获救名单。错过的旅人安全重新等候，不抹掉之前接回的人数。暂停不推进来客计时和步行。

### 艾达：机芯复位

旧听音顺序游戏替换为三段作者设计的连通谜题：

1. 3×3：固定发条端，旋转直通件接到秒针，先看懂连接。
2. 3×3：从盘里选组件，绕过固定件，安排转角与连接顺序。
3. 4×4：分支传动同时接到秒针与摆轮，再上弦。

组件座有上／右／下／左四个可能接口。整座旋转 90°改变接口方向，相邻接口相对才连通。系统从左侧发条做连通遍历，连上的齿轮转动、变亮；目标还必须有朝外的接口，不能仅因走到边缘就算完成。

拼图先固定关卡、自动验证可解，不随机产生无解局。H 会圈出一个组件并给出下一步建议，不会代替玩家操作。每段保留最近 100 次可撤回动作。已完成段落保存布局证明，加载时重新验证确实连通。

首版仍是可读的机械拼图，并非真实齿比、惯性或擒纵结构仿真。底图不是玩法判定依据。

## 声音与动画

| 行为 | 已接入反馈 |
| --- | --- |
| 拿木偶、落位、靠岸 | 分离的木质触碰音高与音量、双样本轮换、轻微音高变化 |
| 开船 | 短水声、缓入缓出、尾部水纹 |
| 移灯 | 金属拿起、卡位，只有移动时触发低音量轨道摩擦 |
| 旅人通过 | 短脚步接触声、进门落定声、人数更新 |
| 组件旋转与装入 | 分开的棘轮／卡扣触感，组件座短旋转动画 |
| 机芯接通 | 运转齿轮与低音量滴答 |
| 完成 | 原创合成的短暖和弦 |

局部声音遵循现有 SFX 总线，做短间隔限流，暂停／切出窗口停止。艾达暂复用研发的舒缓配乐；米洛和霍克复用商店的港口配乐，通过原有音乐服务淡入淡出，离开后恢复此前场景音乐。这一轮没有新增三首独立原创 BGM。

素材使用说明：木／金属声音复用项目已有 `assets/audio/interface/foley/` 材质音库（含原有合成与已记录来源的音频，参见该目录 `sources.json` 与制作脚本）；水、风、滴答、完成和弦为 `tools/build_activity_accents.py` 可复现的原创程序合成，不冒充新采集的实录。

## 数据接口与旧存档

- 保持原活动 ID：`milo_ferry`、`ada_watch_memory`、`hank_lantern`。艾达名称更新，ID 不改，避免断开手帐、解锁条件和首通奖励的引用。
- 活动记录继续写到 `WorkbenchSession.state.activities`，由既有服务原子提交。
- 正式条件仍为故事 5 章＋2 次满意招待；奖励仍是原专属酒谱＋3 点灵感。
- 首通账本仍使用 `first-clear:<activity_id>`，动画、重复点击和重复领取不会额外发奖。
- 新艾达状态标记 `model: 2`，保存阶段、组件位置与旋转、撤回历史、完成段落、上弦状态。
- 老版未完成听音记录：开始时原子转换到新玩法第一段，并向玩家说明；保留邀请、奖励记录。若写盘失败，不启用未保存的新局。
- 老版已经完成但未领奖：保留完成记录，允许补领，不强迫重玩。领过的奖励仍不会重发。
- 老霍克新增步行进度字段，旧记录缺少该字段时视为尚未开始步行。
- 工作台单杯、顾客订单、仓库与钱包不由小游戏直接修改；正式奖励仍走既有研发账本。

## 验证与下一步

验证包括完整正式／演示流程、鼠标实际拖放、空格旋转、撤回、无效落点、暂停、三关可解、JSON 校验、跨进程恢复、旧存档转换与转换失败回滚、补领奖和重复领奖，以及手帐和顾客服务回归。测试使用独立临时存档，不改玩家真实库存与进度。本轮共 563 项检查通过：机芯规则 180、角色完整流程 264、跨进程恢复 9、手帐 69＋恢复 5、顾客服务 30＋恢复 6。

已有测试进程退出时仍会报告少量 `ObjectDB / resources still in use` 清理警告；检查断言通过不代表该项目级警告已经消除。本轮未扩大范围处理原有全局资源生命周期。

后续优先根据试玩调整：组件的可读尺寸、灯光强弱、音效响度与船速。更细的木偶侧倾、旅人分肢走路、门轴音、带路径的地图收尾、不同旅人速度，以及独立场景配乐可以继续增加。本轮先使用剪影整体位移与轻摆，不宣称已经有完整逐帧角色动画。
