# 角色小游戏首版：实现与试玩说明

更新：2026-10-09。适用当前 Godot 工程。本文件说明已经落地的行为；人物故事润色、美术精修和难度数值仍可调整。

## 1. 这一版可以做什么

主页点击 **手帐 → 米洛／艾达／老霍克 → 专属小游戏 → 开始游戏**。

三人沿用现有身份、立绘及各自五章故事，补入每章的口味提示、正式邀请条件、纪念物、可操作的小游戏及首通配方。小线羽毛球入口继续保留，黄色生物本次不扩展。

未正式解锁时，手帐也显示演示入口，便于直接体验。界面会明确标注“演示模式”，无需修改剧情、金币或材料来开门。

| 角色 | 已实现小游戏 | 操作与完成条件 |
| --- | --- | --- |
| 米洛 | 把路画到家 · 雨后渡口 | 三名巡路员、三名在押修路工，船载 1–2 人。点击或拖动人物上船，空格或开船按钮出发；船上人物可以下船。有巡路员的一岸，巡路员不能少于工人。全部到对岸完成。Z／右键撤回，H 提示。最短解 11 趟。 |
| 艾达 | 慢半拍的下午 | 四种零件对应四种音高及亮光。先看、听，再按相同顺序点击，或按 1–4。三段分别为 3、4、5 个音。空格重听，出错只重试当前段，不限输入时间；可保留数字顺序提示。 |
| 老霍克 | 风里还有一盏灯 | 鼠标移动或 ↑↓ 切换三条路的灯位。旅人接近后，持续照亮正确道路，累计接回六人。错过的人会安全等候、重新尝试；支持慢速辅助。 |

小游戏使用暖色纸张、木色及原有角色素材；棋子、怀表、灯光与河水由 Godot 绘制，可继续调整。艾达四段音色由程序合成，点击反馈复用现有音效。

## 2. 剧情、口味与正式解锁

完整链路：

**故事对话 → 当前口味提示 → 选酒并冻结订单 → 工作台制作 → 真实交付与满意评分 → 正式邀请 → 首次通关 → 配方与灵感 → 图鉴／研发／酒单。**

每位客人有固定基础偏好，各章事件对酒感、甜、酸、苦产生增减。共接入三人十五个事件。对话结尾补入当天的口味线索；第一句后续闲谈也可提示当前要求。

`taste_event_id` 记录实际说到的事件，如 `ada_03`。顾客订单创建时保存完整需求快照；之后继续对话或修改配置，不会改变已经接受的这杯订单。事件带有 `guest_id`，不会把另一人的事件套到当前客人。

正式邀请条件按角色分别累计：

1. 该角色五章故事均已完成。
2. 至少两个不同来访 `visit_id`，发生已完成的营业交付，客人接收且口味评分 ≥ 70。

拒收、低分、未完成结算、重复读取同一交付、研发和小游戏演示，都不增加满意次数。进度不会因后续不满意而倒扣。

达成条件后，手帐显示邀请与纪念物：米洛“渡口夹页”、艾达“听音零件盒”、老霍克“旧灯油签”。纪念物当前保存在活动解锁记录并展示于手帐，**不是可出售或可消耗的仓库 SKU**。若后续需要实体剧情道具，可再接道具背包接口。

## 3. 演示、正式局与奖励

| 行为 | 演示 | 正式局 |
| --- | --- | --- |
| 进入条件 | 当前测试配置直接开放 | 满足该角色的正式邀请条件 |
| 剧情与库存 | 不修改，不消耗材料和金币 | 不扣材料和金币，不改变工作台半成品 |
| 酒馆时间 | 暂停；离开恢复进入前状态 | 同左 |
| 中途退出 | 演示进度不长期保存 | 保存当前局，回来继续 |
| 获胜 | 仅显示演示结果 | 每个角色首次通关给予专属配方及 3 点研发灵感 |
| 重玩与辅助 | 可以使用 | 可以使用，不扣首通奖励；不会再次发奖 |

奖励配方：

| 角色 | 配方 ID | 中文／英文名 |
| --- | --- | --- |
| 米洛 | `character_milo` | 寄回家的那一页 / A PAGE SENT HOME |
| 艾达 | `character_ada` | 借我一个下午 / AN AFTERNOON TO MYSELF |
| 老霍克 | `character_hank` | 灯下有名 / NAMES IN THE LAMPLIGHT |

配方进入共享图鉴，可从研发的传说研习进入工作台，也可自行加入酒单；**领取奖励不会自动上架**。配方获得、研习掌握、上架是不同记录，获得后可以制作，上架仍由玩家决定。

首版三份酒谱采用能直接试玩的做法：杯内 100 g 方冰，两份；加入非苏打原料，最后加苏打，拖入吧勺轻拌 3–6 秒。米洛、艾达使用高球杯，老霍克使用古典杯。用量来自设计稿，制作流程暂时简化成直接兑和，区别于早期文档里部分酒谱先摇和／过滤再加苏打的方案。

## 4. 后台数据与职责

| 文件／服务 | 职责 |
| --- | --- |
| `data/guest_service.json` | 基础偏好、十五个事件增减、口味提示、原有评分规则。 |
| `data/guest_activities.json` | 活动名称、路由、演示开关、5 章／2 次条件、纪念物、奖励映射。 |
| `data/research.json` | 三份角色配方的原料 SKU、实际用量、杯型、出品冰、制作标准。所有新数值均属试玩配置。 |
| `StoryDialogue` | 故事推进、听到的口味事件、对话归档、手帐解锁镜像。原有主剧情文本继续保留。 |
| `GuestService` | 冻结订单需求；按实际成品评分、交付与销售结算；提供可核对的满意来访记录。 |
| `GuestActivities` | 邀请条件计算、正式／演示分流、局进度与首通奖励的一次性领取。 |
| `guest_activity_rules.gd` | 纯状态规则：渡河安全校验和最短路提示、顺序记忆、守灯计时；不直接写存档。 |
| `guest_activity.gd`／`guest_activity_board.gd` | 页面、输入、暂停、动画、提示、结果窗；显示层不单独修改奖励。 |
| `MenuCatalog` | 将已获得的角色配方并入图鉴和可选酒谱；酒单仍仅保存配方 ID 与售价。 |

活动账本复用库存／工作台的原子存档，增加可选 `activities` 字段；旧存档没有该字段时按空账本读取：

```text
activities
  version: 1
  unlocks[activity_id]: source, day
  runs[activity_id]: id, activity_id, version, mode, state
  rewards[activity_id]: key, recipe_id, inspiration, day, run_id

research.acquired[recipe_id]: first-clear:<activity_id>
research.inspiration: 原值 + 3（仅首通）
```

一次领取把奖励回执、配方获得记录和灵感一起写入。失败时三者都不生效，完成记录保留，结果窗可“重试领取”；离开后再进也会恢复尚未领奖的完成局。已有首通回执时重复领取直接返回成功，不再次加资源。

正式局的离散操作先写存档、再更新界面。写入失败不会悄悄移动棋子。守灯的连续时间在内存运行，接到人、错过、操作灯位和退出时保存检查点；正常退出可恢复当前进度，异常断电可能回到最近检查点，不承诺逐帧保存。

解锁账本是正式邀请的依据；`StoryDialogue.activity_unlocks` 是手帐兼容镜像。启动和剧情／交付更新时会重新同步，避免两个文件只写成功一个就永久失联。菜单启动时若包含角色配方，会等研究账本读取完成再校验，避免先读取酒单而误删新酒。

## 5. 验证与复现

使用 Godot 4.7.2。测试始终为金币、剧情、会话、酒单、库存、工作台和音频设置分别指定 `/tmp` 独立路径，不借用玩家存档。

```sh
python3 tests/run_character_activities.py --godot /你的路径/Godot --graphics
python3 tests/run_guest_service.py --godot /你的路径/Godot
python3 tests/run_guest_journal.py --godot /你的路径/Godot
python3 tests/run_research.py --godot /你的路径/Godot
```

覆盖三个小游戏实际完成、手帐来回跳转、暂停与时钟、演示隔离、十五次剧情提示、冻结订单、真实满意交付、正式解锁、写入失败回滚、首通幂等、退出恢复、奖励配方真实制作和研习、角色酒单独立进程恢复。图形测试额外检查原生鼠标拖动上船并输出画面。

实机截图在本目录的 `试玩截图`。这些是当前运行画面，早期 `预览` 目录仍是概念图。

本轮结果：角色流程与图形交互 238 项、独立进程恢复 8 项；顾客交付 30＋6 项、手帐 69＋5 项、研发 169＋3 项、小线羽毛球演示 19 项，均为零断言失败。已逐张查看三种玩法和结果页截图，并修正立绘遮住规则说明的布局问题。部分测试进程退出时仍报告 ObjectDB／资源释放警告，后续需单独清理；这不等于测试日志完全无警告。

## 6. 后续可以继续改进

- **故事邀请更自然**：当前用对话后的邀请提示与手帐文字完成衔接；下一轮可把渡河夹页、听音练习和灯油签的递交写入分支对话，增加专门演出。
- **美术与手感**：棋子、船、零件和灯光目前是可交互原型，可换为统一手绘素材，再加摆件触感、角色反应和完成动画。
- **重复游玩**：顺序记忆和六人出场顺序暂时固定，便于测试；后续可存储随机种子，增加可复现题库。渡河保留经典规则。
- **难度**：5 章、2 次满意、3 灵感、3–6 秒搅拌及所有当前口味增减均未视为最终平衡。现有评分比较宽容，不能宣称每个事件都必须更换一款酒。
- **奖励展示**：三份角色酒还没有独立成品插画，图鉴沿用现有回退显示；纪念物尚未进入实体道具仓库。
- **容灾细化**：目前保存正式局的逻辑进度，不保存动画中间帧；守灯的意外关闭恢复粒度可以继续细化。
