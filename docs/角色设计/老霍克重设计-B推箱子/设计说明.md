# 老霍克小游戏重设计：灯下有名 · 风沙前的货棚

2026-10-09｜用户已选择 **B：推箱子**。Godot 已实现三关推箱子并替换原三路移灯玩法。本文保留设计过程与扩展建议；具体完成范围和测试结果以 [实现说明](../角色小游戏-v0.3-推箱子与警囚渡河.md) 为准。

## 1. 我希望玩家玩到什么

玩家在老霍克摆出的旧货棚模型中推动物资箱，绕到箱后、腾出通道，把出发需要的灯、油和绳备齐。每关结束，物资之外还会留下一个提供者的名字。

这一版的情感核心是：**救援的故事从有人准备那一盏灯开始。**

小线的小游戏把“童年、陪伴和重新拿起球拍”变成一次能亲自参与的活动。霍克也应该有一件可以和玩家一起做的具体事情：整理当年出发前的货棚。玩家通过推箱子亲手处理被旧报纸省略的准备工作，让他的反思落在动作上。

趣味来自经典推箱子的空间安排：箱子要从哪一侧推、先搬哪一箱、先空出哪个绕行位置。首版让玩家玩懂一个成熟规则，再用货棚的材质、人物反应和结尾赋予它感情。

## 2. 保留人设，调整故事发生的地点

现有故事保留：镇上准备记录风沙救援，旧报纸把霍克写成独自引回整队人的英雄。他确实参与救援，也曾走失；玛莎准备灯和绳，齐恩的账本留下物资记录，尼尔·贝克认路、找回队伍。最后，霍克愿意把这些贡献写进纪念记录。

新的小游戏发生在第五章“这回写全了”之后。老霍克拿来一张货棚草图，摆出木头箱子，说：

> “报纸从我出门那儿写起。可灯不是自己亮的。来，咱们从屋里讲。”

这是他向玩家解释往事的一次桌面复盘，并不宣称完整还原历史空间。玩家移动的是模型里的霍克和物资箱；尝试失败不会改写当年的生死，也不影响已经完成的剧情事实。

叙事分工要准确：

| 人物 | 游戏中怎样被记住 | 避免的写法 |
| --- | --- | --- |
| 玛莎 | 灯具和绳箱上的旧标签、第一关收尾 | 把她简化成霍克凭空获得的道具奖励 |
| 齐恩 | 灯油、搬运顺序与物资核对的账页、第二关收尾 | 写成只有霍克记得数量，旁人都不重要 |
| 尼尔·贝克 | 出发清单旁的路线记号、第三关收尾 | 因本局是推箱子，就把他原本认路的贡献改成搬箱子 |
| 霍克 | 检查清单、把东西备到出口、随后参与接应 | 为了强调他人的贡献，否定他确实帮过人 |

无需创造三个新帮手系统。人物通过物资标签、短对白和最后共同署名可见即可。

## 3. 经典原型与改编边界

规则参考经典 **Sokoban／推箱子**：推动单个箱子到目标格；不能拉箱子，不能同时推动两个箱子。规则依据 [Sokoban 官方说明](https://www.sokoban.jp/rule.html)。本项目重新设计场景、关卡、人物、美术与声音，不采用原作角色或原作关卡。

为什么选择 B：

- 学习成本低，玩家很快知道自己哪里推错了。
- 既有手感，也有思考空间，适合 2–5 分钟的一段相处。
- 不依赖手速，暂停与撤回天然合理。
- 与米洛的渡河安全规则、艾达的组件连接区分清楚。
- 单格移动和明确碰撞易于做可靠的 Godot 原型。

本轮放弃 A 的接力布置和 C 的解绳，不把三种玩法拼在一局里。风沙只承担环境与故事作用；首版不加倒计时、敌人、火势蔓延、油量消耗或随机障碍。

## 4. 完整游玩流程

**手帐进入 → 霍克一句开场 → 货棚第 1 关 → 整理完成与一段记忆 → 第 2 关 → 第 3 关 → 出发清单与共同署名 → 原有奖励结算 → 返回手帐。**

演示模式仍可直接进入，故事邀请和正式首通条件沿用现有系统。已看过的开场可以跳过；关内不在每次推箱时要求确认。

### 操作

| 输入 | 行为与约束 |
| --- | --- |
| 方向键／WASD | 走一格；前方有箱且箱后是空地时，推动一格 |
| 点击空地 | 建议允许人物沿可达空地走过去；只寻人物的路，不自动替玩家推箱或解题 |
| 朝一个方向拖箱子 | 建议作为鼠标辅助：只能请求推一格，人物必须能走到箱后的发力格；不能把箱直接拖过墙 |
| Z／撤回按钮 | 撤回一次合法动作；人物与箱子一起恢复 |
| R／重来按钮 | 重置当前关，不抹掉前面已通过的关卡；只有已经移动过时才提示一次，避免误清局 |
| H／提示按钮 | 先提示思路；再次提示可标出下一次发力位置，不直接把整关摆好 |
| Esc | 暂停菜单，可继续或返回手帐 |
| 空格 | 在关间收尾页继续下一关；关内不与方向输入抢同一个动作 |

鼠标拖动与键盘应共用同一个 `move(direction)` 判定入口。对于不可推的箱子，保留原位并明确说明“后面是墙”“两只箱挤在一起”“需要绕到另一侧”。手感上可以轻微压缩／回弹，不让箱子先穿墙再瞬移回来。

### 物资与目标格

灯箱、油箱、绳箱有不同图案和接触音，底层均占一格、执行相同推箱规则。目标是货棚门前的**备货区**，首版任意箱可放任意备货位；不做“灯只能放黄色格”的额外匹配规则。

这样能保留简单的空间谜题，也避免玩家误以为颜色是规则。画面用统一黄铜边框表示备货位，箱子入位后边框亮起，移出后熄灭。计数始终重新计算，不以入位动画累加。

## 5. 三关草案与难度节奏

以下草案是独立设计的逻辑盘面，已用合法移动状态的广度优先搜索验证可解。解法保存在 [关卡草案与解法.json](关卡草案与解法.json)。当前统计为最短**行走步数**对应的推箱次数，不宣称推箱次数也是最优。

图例：`#` 墙，空格为地面，`@` 人物，`$` 箱子，`.` 备货位。正式美术可以向外延展，不能改变这些碰撞关系。

### 第 1 关：灯不是自己亮的

6×5、1 箱、1 目标。箱子在目标右边，玩家在其左下方。直接向上并不能把它拉回来，需要绕到右边推向左侧。

```text
######
#    #
# .$ #
# @  #
######
```

验证解法：右、右、上、左；共 4 步、1 次推动。建议作为约 20–40 秒的教学，不强加计时。

入位时，箱盖里的灯罩轻响，霍克说：

> “玛莎把灯擦过。风里找人的时候，玻璃脏一点，都不一样。”

这一段主要教“绕到箱后”，不额外引入油量系统。

### 第 2 关：账上那两笔

7×7、2 箱、2 目标，中间有障碍，必须分别绕行。目标是让玩家形成“先想站在哪里，再想箱子去哪”的习惯。

```text
#######
# . . #
# $ $ #
#  #  #
#  @  #
#     #
#######
```

已验证最短行走解法 9 步、2 次推动。这是一关轻过渡，不把简单关包装成高难谜题。正式试玩若过短，可增加一个绕行墙角，修改后重新验证，不能只凭画面加障碍。

霍克的反应：

> “齐恩记的不是两只箱，是那晚够不够用。账上那两笔，比我的名字早。”

### 第 3 关：先给别人留条路

8×7、3 箱、3 目标。障碍让部分目标不能直推到达，需要为箱子和人物预留绕行空间，再决定物资的顺序。

```text
########
#  . . #
#  #   #
# $$ $ #
#  .#  #
#  @   #
########
```

已验证最短行走解法 28 步，其路径包含 10 次推动。完整序列放在 JSON 中，玩家提示不直接显示整条答案。

最后一箱入位后，镜头不跳“传奇英雄”，而是看向门边的出发清单。霍克把“尼尔·贝克”补全：

> “东西备齐了，也还得有人知道路。那晚，是尼尔回来找的我们。”

**完成不是比最少步数，而是备齐后还记得是谁帮了忙。** 首通奖励不因撤回、提示或步数减少。重玩可显示个人最少推动数，但不增加金币刷取渠道。

## 6. 失败、撤回与耐心

箱子推到非目标死角、两箱互相卡住，是经典玩法的后果。允许玩家做出这些合法但不利的移动，然后给出反馈，不把所有坏选择提前禁止。

建议分层处理：

1. 撞墙或同时推两箱：动作没有发生，小幅回弹，底部说明原因。
2. 推进明确死角：动作已经发生，短镜头停留，霍克叹口气：“又把门堵上了。往回挪一步。”底部突出 Z 撤回。
3. 玩家选择当前关重来：回到该关初始盘面，保留前面关卡的完成记录。

首版只检测明确的非目标角落与简单死格。不要用不完整的死锁检测武断宣布所有复杂局面无解，也不要每一步弹一个失败窗。后续若加入失败 CG，仍应可以直接撤回，不需要重放全套剧情。

## 7. 美术与 UI

预览：[B · 风沙前的货棚](B-风沙前的货棚-概念.png)

这张图用于确认材质、氛围和布局，**不是逻辑盘面的截图**。生成图中的格数、备妥计数和箱子位置不作为最终关卡数据；正式版按上述经过验证的盘面生成交互层。空头像框在实装时使用现有老霍克立绘。

- 主视角是俯看木质货棚模型，适当保留箱子和墙的厚度；透视不能让玩家误认格子邻接。
- 地面使用木板和黄铜钉暗示网格，不用耀眼棋盘线。
- 可推箱用独立美术，墙边装饰箱与可推箱在轮廓、底座和摆放方式上明显不同。
- 出口露出海港与风沙，室内仍有暖灯，保持原游戏温暖的港口西部画风。
- 顶部只留关卡、备妥数量、暂停和返回；步数可以低权重显示。
- 底部纸条动态说明当前动作；人物短对白不挡可推区域。
- 参与者姓名写在清单与标签上，避免做成资源条或技能等级。

建议最小可读单位为 64–80 像素一格，以实际窗口测试为准。UI 缩放时同步命中区，静音也能辨别推成功、被阻挡和入位。

## 8. 手感、特效和音效

下面的时间是建议起点，实机试玩后调整，不作为定稿。

| 行为 | 动画与特效 | 声音 |
| --- | --- | --- |
| 普通移动 | 人物约 0.10–0.14 秒跨一格，脚底贴地，不滑冰 | 轻木板脚步，至少轻重两组 |
| 推动起势 | 身体前倾、手靠箱沿，再整箱平移；阴影连续跟随 | 短木头接触 |
| 箱子行进 | 约 0.16–0.22 秒；细尘屑沿地板移动，不做大块烟雾 | 低木擦声，只在移动时播放 |
| 灯箱落定 | 箱体轻震，挂签迟一点停下 | 木碰＋很轻的玻璃／金属接触 |
| 油箱落定 | 重一点、回弹更短 | 木碰＋低液体晃动，不做汽油爆炸声 |
| 绳箱落定 | 更软的收尾 | 纤维摩擦与绳结轻碰 |
| 撞墙 | 人物发力后回稳，箱子不越过格子 | 低闷音，一次即可 |
| 进入备货位 | 地面黄铜边短亮，清单划一小笔 | 单次卡位与纸笔声，不播放连续金币音 |
| 撤回 | 回播最近一步较短的位移动画 | 轻回拖声；不重复播放入位奖励音 |
| 全部备齐 | 门外风声变轻，灯升亮，名单被摆正 | 木门、远处人声和短暖和弦 |

键盘长按建议设短重复间隔，动画期间最多缓存一次有效方向；不能把一串长按积压成玩家松手后箱子继续跑。底层以离散动作判定，不用物理碰撞决定箱子究竟在哪格。

音乐建议沿用港口舒缓主题的小编制变奏，以木吉他／轻手风琴为方向；不需要为了风沙加入持续阴森低音。素材要在实现时实际试听和记录许可；本方案未声称新增音频已制作。

## 9. 与口味、剧情和奖励的关系

小游戏沿用原故事邀请：第五个关键章节完成＋两次满意招待。满意招待应继续取现有正式交付记录，不另造小游戏好感值。

霍克基础偏好依旧约为酒感 65、甜 15、酸 10、苦 30；对应第五章的当次目标约为 60／20／10／25。这里沿用现有设计口径，不因推箱子成功就永久改变口味，也不让玩家用重复小游戏刷满意招待次数。

完成后仍走已有 `character_hank` 专属酒谱与 3 点灵感；主题可以继续使用《灯下有名》。手帐增加这段已观看的收尾文本时，应使用稳定内容 ID 去重，不能每次重玩都累积同一句话。

建议纪念页落款：

> 玛莎备灯与绳，齐恩记下物资，尼尔认路，霍克参与接应。还有没能核实的名字，留出一行。

这一行空白不是隐藏收集任务的强制暗示。它表达他们愿意承认记忆仍有缺口。

## 10. Godot 与后台实施方案

这一节是后续开发建议，当前没有把以下脚本接入正式玩法。

### 建议拆分

- `hank_crate_rules.gd`：地图校验、走格、推箱、撤回、死格与完成判断。
- `hank_crate_board.gd`：木棚、人物和箱子绘制、点击／拖动、位移动画。
- 复用现有 `GuestActivities`：演示与正式局、原子保存、奖励幂等。
- 复用公共小游戏外壳：暂停、返回、音乐所有权与酒馆时间恢复。

### 配置与状态

关卡定义建议包含 `level_id`、`layout_version`、尺寸、墙集合、目标格、玩家起点、稳定箱子 ID 及类型、对白 ID、已验证参考解法。解法放测试与设计数据，不直接作为玩家自动通关接口。

运行状态建议保存：

```text
model: 新版本号
level_id / layout_version
player_cell
crates: [{id, type, cell}]
action_history: 最近合法动作与前态
completed_levels: 已完成关卡及验证信息
steps / pushes / hint_count
phase: playing | stage_clear | complete
won
```

每个移动按同一顺序执行：检查游戏是否可操作 → 验证人物目标格 → 若有箱，验证箱后格 → 生成新状态 → 正式局保存成功 → 执行动画与声音。写盘失败保持原状态；动画重播不能重算推动数或奖励。

完成条件是 `所有箱位置都在目标格` 且箱子数量与配置一致；从状态重算备妥数。不能用“曾经播放过几次入位音效”判断完成。正式领奖前再校验三个关卡的完成记录。

返回手帐保存当前稳定格子状态。若离开时正在播放推动动画，以已经提交的动作末态为准；恢复时把人物和箱子画到末态，不再次执行推动。

### 替换旧移灯存档

为了兼容手帐链接，可以保留既有活动 ID `hank_lantern`，用新的 `model` 区分推箱子；显示名称更新为《灯下有名 · 风沙前的货棚》。旧版移灯字段不能解释成箱子坐标。

- 旧版未完成：说明玩法已更新，从推箱子第一关开始。
- 旧版已完成但未领：允许继续领取原奖励，不要求重玩。
- 已领过：首通账本保持 `first-clear:hank_lantern`，换玩法不再发一次。
- 正常与演示分离；推箱子物资是场景道具，不扣酒馆仓库的灯油、金币或酒料。

## 11. 开发顺序和验收

建议先做第一关的灰盒，确认方向键、推一格、撤回、死角反馈，再接美术。之后增加第二、三关和收尾，最后替换旧入口与迁移存档。

验收重点：

1. 三关均能按验证解法通关，行走与推箱计数正确。
2. 箱子只能推一只、不能拉、不能穿墙；鼠标和键盘判定一致。
3. 连续按键、松手、暂停、撤回不会留下半格位置或额外动作。
4. 进入和移出目标格都正确更新备妥数，没有重复计数。
5. 关内重来只重置本关；退出和进程重启能恢复人物、箱子与历史。
6. 无效操作与实际死角反馈区分，普通试错不扣首通奖励。
7. 演示不写正式进度；旧移灯存档可读，领奖只发生一次。
8. 在 800×450、1280×720 和大窗口下能辨认墙、箱、目标与发力位置。

待试玩决定：第三关是否需要简化、鼠标自动走到发力格是否足够自然、提示分几层、是否展示个人最少推动数，以及货箱轻微材质差异的响度。首版不添加搬运重量、人物体力或随机生成关卡。
