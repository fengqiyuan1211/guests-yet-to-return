# 本地服务自动启动（2026-10-07）

在桌面版 Godot 中按 F5 或启动主游戏时，LocalServices 自动加载并后台检查酒图服务和客人反馈服务。服务没有运行时自动启动，已健康运行时复用。不会因为游戏启动就调用付费模型，也不会重复支付或改动存档。

酒图默认地址为 http://127.0.0.1:8787，顾客反馈为 http://127.0.0.1:8788/feedback。自动启动后台处理，不阻塞主页；首次出图或首次点评会等对应服务就绪。游戏退出后服务保留，方便后续重开复用，正在画的图片可以继续完成。

模型密钥分别保存在 services/cocktail-image-service/.env 与 services/customer-feedback-service/.env。DeepSeek 使用 DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_MODEL；没有填写时游戏仍使用现有本地点评，不会假称是大模型反馈。

启动器自动查找服务目录的 .venv、电脑上的 Python 和已安装的 Codex Python。需要 Python 3.10 及以上；图片服务还需要 Pillow。朋友拉取代码后依旧需要自行配置 .env 和 Python 依赖，不共享密钥。启动失败的日志位于 user://local_services/image.log 和 feedback.log，启动状态位于同目录 startup-*.json。

代码入口为 scripts/local_services.gd 和 services/auto_start.py。data/diy_image_service.json 或 user://diy_image_service.cfg 控制酒图地址；客人反馈的 --feedback-url 参数仍有效。指定远程地址时不在本机拉起对应服务。

默认在无界面测试或指定独立存档时不启动服务；--start-local-services 可明确启用，--no-local-services 可关闭。移动端和网页导出不能在本机启动 Python，仍需使用部署好的服务。桌面导出版需要将 services 文件夹放在可执行文件旁，同时在服务端配置密钥。

## 额外装饰限制

提示词版本为 diy-cocktail-garnish-whitelist-v5，保留目前钢笔淡彩手绘画风。实际装饰及明确留杯固体是唯一可见食材依据；没有选薄荷时，明确禁止薄荷叶、薄荷枝和绿色装饰叶。参考图片只选其可见食材没有超出目标清单的样例，文字 few-shot 仍保留两组。

这会减少参考图带入装饰的概率，但提示词本身不能保证模型每次完全遵守。图片仍须在确认保存前查看杯型、颜色和装饰，没有加入自动语义识别。
