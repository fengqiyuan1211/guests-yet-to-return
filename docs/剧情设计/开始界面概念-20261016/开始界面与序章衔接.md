# 《致未归的客人》开始界面与序章衔接

> 2026-10-16 接入更新：已采用 A 并接入 Godot；本页保留原设计方案，实际完成项与限制见 [Godot 接入说明](Godot接入说明.md)。

版本：2026-10-16，视觉选型稿。已交付三张开始界面概念图、一张蓝色回响酒图和独立浏览器试听预览。本轮没有修改 Godot 场景、正式酒谱或存档。图片中的文字是排版示意，正式 UI 使用 Godot 控件独立渲染。

## 1. 本次已经确定的方向

新酒与旧回响合并，统一展示为 **回响 / Echo World**。Echo World 按用户指定保留，不自行改为 Echo Word。会议称呼“回声”和旧英文 ECHO WORD 仅作为历史来源；归航 / homeward 暂不合并。

回响使用 Last Word 酒图的杯型、构图、手绘线条和玻璃高光，酒液改为明亮蓝色。经典 Last Word 仍是另一款酒，保留原配方和原酒图。

![蓝色回响](images/回响-Echo-World-蓝色概念.png)

新图是透明背景的视觉参考，绘制水彩纹理和浅蓝高光；正式使用前需在深、浅 UI 底上检查边缘。视觉填充高度不是配方容量标尺。此前草本候选配方不含可解释蓝色的材料，不能直接拿来宣称蓝色配方已完成。接入时需统一有色原料、库存单位、属性、用量与混色数据，让实际成品颜色可追溯；不通过酒名给成品强制染色。

## 2. 三个开始界面方向

共同基调：暖色手绘，木材与黄铜，夕阳映在蓝色海面上。画面温柔、清楚、留有呼吸空间。伤感来自等待、空椅子和音乐中未完全收束的旋律，不依靠阴森的雾、黑暗画面或哭泣人物。

### A · 归港余晖

![A 归港余晖](images/A-归港余晖.png)

从码头望向右侧岛上的酒馆，左侧放标题和竖排菜单。远处窗灯与近处灯笼相互呼应，海面占比较大。

- 优点：一眼看到海岛、港口和酒馆，世界观最直观；菜单位置稳定。
- 情绪：像在旅程结束前看见一处可以歇脚的地方。
- 动态重点：前景浪纹、夕阳反光、小船轻微起伏、窗灯轻闪。
- 需要控制：海浪不能像风暴一样激烈，选中菜单时附近反光要克制。

### B · 留一盏灯（推荐）

![B 留一盏灯](images/B-留一盏灯.png)

视点在酒馆门廊，左侧空椅、信与暖灯，右侧是海面和菜单，夕阳落在远处小岛旁。

- 优点：直接呼应剧本里的空椅子、信件与留下的酒馆；景色也足够开阔。
- 情绪：这里已经为某个人留了位置，玩家从开场就能感到“未归”的主题。
- 动态重点：海上碎光、灯焰、轻晃的招牌和极轻的海风。
- 需要控制：概念图上招牌英文只是美术占位，正式版本换成统一游戏标识；前景木纹适度简化。空椅子保持静止，不做幽灵式晃动。

建议以 B 为开始界面，A 的抵岛构图可延续到 S05 海路 CG；这能把同一世界的两种视点连起来，不需要把三版全部塞进主菜单。

### C · 潮汐来信

![C 潮汐来信](images/C-潮汐来信.png)

标题在上方居中，菜单顺着留白向下排列。酒馆缩小到左侧海岸，天空、海面与弧形岸线形成主要画面。

- 优点：最轻盈、明亮，适合突出安静与诗意。
- 情绪：世界很大，岸边仍有一盏小灯。
- 动态重点：浅滩潮线缓慢推进又退回、云影、远处船影。
- 需要控制：天空和浪花细节继续做减法；中央菜单保持稳定对比度。

## 3. 背景如何动

不是将整张图左右移动或对整屏做波纹。正式制作分开以下层，木头、岛屿、标题与按钮保持稳定：

| 图层 | 动作建议 | 制作与边界 |
| --- | --- | --- |
| 天空与远山 | 基本静止；薄云极慢移动 | 无缝云层，约 45—90 秒一个缓慢过程；数值可调 |
| 海面 | 局部法线/UV 小幅变化，远处更慢更细 | 只影响水域遮罩；不拉扯岸线、建筑、文字和船 |
| 夕阳碎光 | 不同浪脊错开明灭 | 顺反光带分布，避免整片海同步呼吸 |
| 岸边潮线 | 渐进、停留、回退 | C 的重点；建议 7—12 秒节奏，不能均匀机械往返 |
| 小船 | 小幅上下与转角变化 | 围绕系缆位置，运动不超过视觉可接受范围；不在菜单后反复穿行 |
| 灯火与窗光 | 极轻的不规则亮度变化 | 暖光局部叠加，禁止快速闪烁 |
| 招牌、帘角 | 偶尔受风轻动 | 适量即可；不让所有物体持续摆动 |
| UI | 聚焦时文字微亮、细金线出现 | 约 0.15 秒；不放大整块按钮，不每次弹说明窗 |

预览页目前只用完整概念图叠加局部潮光和灯光，演示动态幅度；不是已经分层制作好的真实海浪动画。正式选择构图后再交付无字底图、水面遮罩、前景、船、灯光等分层素材。

保留“减少动态”开关；关闭后仍显示完整静帧。窗口失焦或最小化时暂停无必要的视觉更新，背景音服从玩家设置。固定夕阳是开始界面的情绪场景，进入游戏后大厅仍使用现有时间与日夜系统。

## 4. BGM 与环境声

主题曲暂名 **《留灯的海岸》**，是配乐方向名称，尚无此名的正式录音。

| 项目 | 建议 |
| --- | --- |
| 情绪 | 温柔、能休息、略有遗憾；温暖约占八成，伤感藏在末句和留白里 |
| 节奏 | 约 68 BPM 的舒缓 4/4；作为作曲起点，不是定稿参数 |
| 主奏 | 柔软的钢琴短旋律；尼龙弦吉他轻分解和弦，与既有酒馆音乐的木质听感相连 |
| 底色 | 很轻的低音弦乐或空气感长音；避免阴森低频、钟表恐怖感和浓重弦乐悲剧高潮 |
| 旋律 | 四至五个音的短动机，末尾留一点余韵；抵岛时再次出现同一动机 |
| 循环 | 建议先制作约 80—100 秒的无缝版本，开头不强拍砸入，结尾不突然静音 |
| 环境声 | 低音量远海浪、偶发绳索或风声；海鸥不要高频叫个不停 |
| 点击 | 轻木响或柔和纸感短声；开始游戏只给一次温和确认，不用强烈胜利音效 |

浏览器预览暂时引用项目已有的 **Laura – Soft Acoustic Guitar Folk Instrumental / kaazoom**，只供比较“木吉他＋夕阳海面”的搭配，不称作新作或最终专属标题曲。来源与已有授权记录见项目 [音乐说明](../../../assets/audio/music/README.md)。用户试听后表示非常喜欢此曲，现将它提升为开始界面的优先配乐候选。另提供 [相同原始 MP3 的独立副本](配乐/Laura-kaazoom-开始界面试听.mp3) 与 [来源说明](配乐/来源说明.md)。未新增下载或上传第三方音乐。海浪声是预览页实时合成的音色草图，不是真实海边录音。

首次打开预览静音，点击“试听配乐”后才播放；音乐与海浪音量可分别调整。进入正式 CG 时，音乐建议约 2 秒渐出，公寓场景先留下城市环境声；来信/回忆短暂带回动机，抵岛时更完整地响起。进入工作台后沿用现有切曲服务渐变，不让主题曲与工作台 BGM 并行叠放。

## 5. 玩家从开始界面到第一杯

### 首次新游戏

开始游戏 → 建立新旅程记录 → S01 公寓与失败后的生活 → S02—S03 酒友相识及回响试调 → S04 来信 → S05 海路 → S06 椅子与交接 → S07 推门、翻开旧酒谱 → S08 第一杯回响教学 → S09 翻转营业牌 → 正常接客。

不先让玩家在正式大厅里点菜单再突然播放开篇。点击开始后直接淡出菜单，进入剧情；从抵岛镜头自然切到现有大厅，再把视线移到工作台。

开篇沿用 [逐场文本](../开篇重构-20261016/剧情大纲与逐场文本.md)，第一杯沿用 [教学设计](../开篇重构-20261016/教学与回响配方方案.md)。第一次动手前约 4—6 分钟是当前文本估计，需试玩计时；读速由玩家掌握，不强制等待每张 CG 播完。

### 已有进度与自由调酒

| 状态 | 菜单与去向 |
| --- | --- |
| 完全新档 | “开始游戏、设置、制作名单、退出游戏”；不显示不可用的继续按钮 |
| CG 中途退出 | “继续旅程”回到已保存的剧情节点；不重置已选对话 |
| 教学中途退出 | “继续旅程”恢复当前教程、容器与真实动作记录 |
| 已结束序章 | 继续原营业进度、当前模式、手帐、客人及小游戏记录 |
| 升级前的旧档 | 直接继续；不能因缺少新字段被识别为新玩家而强制教学 |
| 玩家主动开始新旅程 | 首版沿用现有单档管理前，必须明确说明与备份将重置的记录；不能只清大厅而留下其他旧档造成串档 |
| 自由调酒 | 现有入口和独立状态保留；从旧档继续时保留原模式，不用新教程覆盖自由调酒 |

概念图显示首次启动的菜单。正式有存档时，“继续旅程”成为第一项，“新的开始”是次级入口。是否扩展多存档槽另做实现任务，不能在本轮设计中假定现有项目已支持。

## 6. 剧情与教学的交互

空格/鼠标推进对白；一次按键只完成当前文本展示或推进一次，不能跨场景连续触发。选项出现时用方向键选、确认键提交，也保留鼠标点击。已读文本可快进。

“跳过剧情”去 T00 教学说明，不跳掉新手操作；“跳过教学”是另一项，进入正常游戏但不生成虚假的完美作品、顾客评价和销售金币。回看 CG 与练习教学只改变回看上下文，不重发配方或推进客人章节。

教学仍以拖动与空格为主：糖浆量取 → 转移 → 薄荷轻压 → 其余材料 → 加冰 → 摇和 → 过滤出杯。顺序需随最终蓝色配方修订，目标量与黄金刻度线从同一配方快照读取，不硬编码在对白里。

## 7. 与当前 Godot 项目的衔接建议

以下为待实施设计。已检查项目目前主场景是 `scenes/home.tscn`，`home.gd` 在启动时绑定营业并保存，`SaloonAudio` 在自动加载时直接播放大厅音乐。不能仅在 home 上覆盖一个图片菜单就算完成开始界面。

| 部件 | 职责与必要调整 |
| --- | --- |
| 启动路由 | 决定处于 title / opening / tutorial / gameplay，在进入大厅前处理首次与旧档兼容 |
| `title_screen.tscn`（新增建议） | 动态背景、可用菜单、设置与键鼠焦点；不发原料、不创建顾客订单 |
| `opening_story.tscn`（新增建议） | 消费 S01—S07 文本与 CG 配置；管理跳过、回看、节点恢复 |
| 教学引导层（新增建议） | 观察真实工作台事件，切换高光；不自己再扣一次材料，不复制一套调酒系统 |
| `GameSession` | 增加带版本的开篇状态、旧档迁移；保留当前营业、故事与访问数据。对实际分散存储的模块做一致性恢复 |
| `TimeManager` | 在标题、开篇、教学期间暂停营业计时和自动开店；进入正常游戏才恢复，不影响玩家已有时间 |
| `SaloonAudio` | 增加 title / opening 上下文，并沿用音乐音量与淡入淡出；启动时不先播放大厅 BGM 再抢切 |
| `PlayModes`、手帐和小游戏 | 保留原有模式边界与奖励记录；开篇不冒充正常满意招待 |
| 图鉴与配方 | 回响统一身份与版本，别名迁移可追溯；经典 Last Word 独立不覆盖 |

建议持久字段：`opening_version`、`phase`、`node_id`、`choice_flags`、`tutorial_session_id`、`tutorial_recipe_version`、`tutorial_step`、`tutorial_status`、一次性配方领取凭据。节点状态与容器/消耗应在同一事务边界保存；从退出恢复不能少料却找不到液体，或恢复液体但未扣料。

旧档应通过已有存档内容和版本迁移识别，不能只靠 `opening_completed == false` 判断首次。损坏存档需保留原文件并提示恢复，不能作为“新档”静默覆盖。

## 8. 实施顺序与验收

1. 选定 A/B/C 构图，确认回响蓝色方向；提取无字背景及动态分层素材。
2. 做开始界面和启动路由：新档进入剧情，旧档继续，音乐及营业时钟不提前启动。
3. 按 S01—S07 接文字、CG、少量选择及恢复点；再接既有工作台教学。
4. 统一蓝色回响的配方、颜色、图鉴、故事及教学目标；没有最终配方前先用开发占位，不发布伪称已校准的数据。
5. 接 S09 开门；验证真实接待、手帐、自由调酒、小游戏与旧存档均可继续。
6. 最后调海浪、灯光、音量、文字可读性和节奏。

验收重点：首次流程可完整走通；所有退出点可恢复；跳过不发假奖励；重试不重复扣料或领配方；标题阶段不计营业时间；切场景只播放一组音乐；1280×720 下文字清楚；减少动态生效；桌面旧档不被重置。
