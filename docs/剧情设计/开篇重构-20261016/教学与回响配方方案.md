# 第一杯回响的配方试调与交互教学

> 2026-10-16 最终本轮确认：弃用此前蓝橙/薄荷候选，回响改用午夜蓝草本酒（虚构 Bleu de Minuit），与金酒、樱桃利口酒、青柠汁各 22.5 ml，钴蓝酒体。现行步骤和数据见 [Godot 接入说明](../开始界面概念-20261016/Godot接入说明.md)。以下旧候选与额外轻压教学设想仅保留设计演变记录，不是当前执行配方。

版本：2026-10-16 设计建议。本文中的新配方、引导状态及教学专用资源尚未实现；沿用工作台已有操作能力，不将设计当成已经运行的功能。

## 一 配方依据与限制

经典 Last Word 按 IBA 配方由金酒、绿查特、Maraschino 樱桃利口酒、鲜青柠汁各 22.5 ml 构成，加冰摇和、过滤进入冰镇鸡尾酒杯。这份标准保留独立身份，不因新剧情酒而改写。[IBA 配方](https://iba-world.com/iba-cocktail/last-word/)

绿查特的官方资料列出 55% vol.，并注明使用 130 种植物性材料。它同时带来酒精、甜味和复杂的香气，因此不能把“用薄荷替代它”当作已经成立的等效替换。[Chartreuse 官方原料与酒精度资料](https://www.chartreuse.fr/qr/verte-011-gb/)

本次会议所说的价格压力用于主角的个人消费动机，不写入未经核实的市场售价，也不声称世界各地此时都买不到绿查特。游戏里的更低成本需要用本项目库存单价重新计算。

## 二 回响试调候选

已确认名称：回响 / Echo World，与旧回响合并。已确认视觉目标为沿用 Last Word 杯型的通透蓝色酒液。下列是为了现实试调与玩法讨论提出的第一版，不是经典酒谱，不是已验证的复刻，不是正式数值。

目标：保留金酒、青柠、樱桃利口酒的联系，减少对绿查特的依赖，尝试让新鲜草本与柑橘气味更突出。它会丢失原酒一部分复杂性；这一点可以成为人物交流内容，不必掩盖。

### 候选 A 新鲜草本方向

| 材料 | 建议试调量 | 作用及待校核项 |
| --- | --- | --- |
| 金酒 | 30 ml | 基酒；不同产品的杜松与柑橘表现不同 |
| Maraschino 樱桃利口酒 | 15 ml | 保留与原酒的联系；不是随意换成甜樱桃糖浆 |
| 鲜青柠汁 | 20 ml | 提供酸度；需按原料实际酸度试饮调整 |
| 1 比 1 简单糖浆 | 5 ml | 补充甜度；糖浆浓度改变时不能直接沿用该量 |
| 新鲜薄荷叶 | 暂用中等大小 4 片作试调起点 | 大小差异明显；正式游戏统一片数、库存与表现，不能擅自换成已定稿克数 |
| 新鲜橙皮 | 暂定 1 小片 | 作为香气方向候选；首版教学可暂不强制要求挤皮油动作 |

液体基量合计 70 ml，不含融水。预估稀释后的体积只能在完整制作后测量；不把杯子视觉画满作为正确用量依据。正式出品还要核对现有杯型容量与系统融水模型。

建议过程：薄荷与糖浆放入摇壶底部，轻压到叶片舒展；加入其余液体与制作冰；盖壶摇和；用过滤方式挡住冰与叶片，倒入冷却的鸡尾酒杯。橙皮香气步骤可先由过场说明承担，或待原料与交互核实后纳入。没有实现的挤皮油动作不能仅在配方中写上就视为可玩。

此方案会增加轻压操作，但可以使用现有工作台的轻压棒。若测试发现第一杯负担过重，可将本步骤作为导师协助示范，玩家仍亲自量取、转移、摇和与出杯。

### 候选 B 使用预先制好的草本调和液

【备用建议】将薄荷等前处理封装为一瓶“回响用草本调和液”，让新手主要操作液体量取。只有明确调和液组成、批次产量、保存规则、成本与属性后才能采用，不能凭空加一瓶万能绿酒。

本次优先用 A 做真实试调，再根据教程试玩负担决定是否值得开发 B。不要为赶进度把尚未验证的预调液直接加入商城。

### 试调后如何决定

同时品尝经典版本和候选 A，记录酸甜平衡、香气、苦涩、稀释体积和每杯成本。每次只调整一个方向，保留实际用量。至少区分“自己的清新改编成立”与“复刻绿查特成功”这两个完全不同的结论。

成本按实际取出量计算：每种原料取出量 × 库存单位成本，再加消耗的薄荷、橙皮等；洒漏仍计成本。未拿到一致的采购口径前，不在对白里宣称便宜几倍。

## 三 属性与颜色如何进入现有系统

1. 回响与 Last Word 保持不同 recipe ID。新回响合并旧回响身份，旧名 ECHO WORD 与会议称呼回声作为来源别名；若发现旧存档中的回响 ID，明确迁移至统一身份，旧配方版本与历史记录不改写。当前正式库尚未收录 B1 回响，具体 ID 在接入时核查。
2. 目标酒感、甜、酸、苦通过确认配方及统一评价模型校准，不手填一组看上去更强的 0—100 数字。
3. 新鲜草本、柑橘香作为风味标签；“回响”的故事含义作为剧情标签。它们不是特殊 Buff，也不强制增加顾客满意度。
4. 自由改动仍生成独立单杯记录。教学目标配方快照与实际酒杯分开。
5. 用户已确认蓝色视觉方向，图鉴和 CG 的杯型沿用 Last Word。概念图见 [蓝色回响](../开始界面概念-20261016/images/回响-Echo-World-蓝色概念.png)。图鉴插画可有艺术表现，但工作台仍按实际原料混色，不能因为名字叫回响就把任何成品强制变蓝。
6. 上述候选 A 是此前提出的草本口味试调起点，不足以解释蓝色外观，因此暂不能作为蓝色版正式配方。蓝色版还须确定相应有色原料及比例，并把它的甜度、酒精、成本、库存消耗、颜色参数一起纳入模型。优先保留真实材料逻辑；不把透明金酒、糖浆或现有樱桃酒随意改蓝，也不暗中添加只改变颜色的免费材料。
7. 不凭“用了便宜原料”降低品质，也不凭“原创”强行评成完美。客人口味、制作质量与剧情反应继续独立判断。

## 四 单步高光教学

### 玩家看见的布局

保留第一人称工作台、左上角配方纸条、右侧备料菜单、下方浅色底深色字提示。只有当前目标有柔和金边；其他元素降低一点视觉竞争，但仍能辨认，不用整屏变黑。

提示包含一个动作、一条目标信息和必要按键，例如“把糖浆拖到量酒器，接近 5 ml 红线时按空格”。玩家完成后下一条自动出现，不再加“我知道了”“确认倒入”等按钮。

不频繁弹管家头像压住工具。首次介绍用一行旁白，后续反馈短暂显示在原提示区。

### 教学状态表

| 状态 | 引导与玩家动作 | 前进条件 | 不符合时如何反馈 |
| --- | --- | --- | --- |
| T00 认识台面 | 高亮酒谱、杯子、量酒器，逐个短介绍，可跳过介绍 | 玩家开始制作 | 不要求逐个阅读悬浮窗 |
| T01 选杯 | 高亮杯型菜单，再落到右上方杯位 | 正确杯型已选且可用 | “这杯用这只杯子试，别急。”提供替换入口 |
| T02 取糖浆 | 备料中高亮糖浆，拖至量酒器 | 量取交互真正开始 | 拖错位置时只提示目标，不自动扣第二次料 |
| T03 停止量取 | 显示目标红线与实际刻度，空格停止 | 倒入结束且数量已记账 | 适量偏差保留真实数值；超差显示调整或教学重试 |
| T04 转入摇壶 | 量酒器与摇壶之间短虚线路径 | 内容从量酒器转入摇壶 | 不重复扣库存；杯满时按真实容量处理 |
| T05 薄荷与轻压 | 高亮薄荷与轻压棒；拖入、上下拉动 | 达到配置的轻压教学条件 | 叶片渐变与短反馈同步；不固定写死几秒必定完美 |
| T06 其余液体 | 金酒、樱桃利口酒、青柠汁逐项高亮，沿用量取与转移操作 | 配方所需液体均有实际记录 | 每项显示尚缺量，目标线跟随当前目标更新 |
| T07 加冰与盖壶 | 高亮冰菜单、摇壶盖 | 冰的实际质量达到教学配置且壶盖状态正确 | 显示已加克数、每份克数；不能只写“加一份” |
| T08 摇和 | 高亮壶身；拖起、快速往复 | 检测到有效摇和并达到配置目标 | 显示当前力度、进度及可以停止的提示，不按按住时间冒充有效摇和 |
| T09 过滤出杯 | 高亮滤具和成品杯 | 发生有效液体转移，液体实际进入成品杯 | 满杯则停，余液留原容器；不删除多余液体 |
| T10 试饮反馈 | 展示真实成品和制作记录 | 玩家读完反馈或选择调整 | 对应酸甜与漏料反馈，不无条件播放夸奖 |
| T11 记录与开门 | 可选写备注，之后翻转营业牌 | 序章完成写入成功 | 保存失败保留现场，允许重试，不重复赠送资源 |

本版统一顺序：糖浆首次量取 → 转入摇壶 → 薄荷轻压 → 金酒等液体 → 冰与摇和 → 过滤。首个材料为糖浆，目标为 5 ml，文案与红线从配方生成；金酒 30 ml 是之后的一次量取，不重新讲完整教程。

5 ml 对首次操作可能偏难，是需要试玩验证的点。建议首次量取降低指针移动速度、放大刻度显示，仍保留真实停止量，不偷偷将黄金区间吸附为固定正确值。是否调整教程配方，应在试饮后共同决定，不能只为方便操作任意加糖。

### 自由度与新手容错

玩家从配方选择“开始教学”后，获得明确目标，但工作台仍保留真实数量、颜色、容器转移与库存逻辑。引导层观察动作结果，不另写一套假的倒酒实现。

默认轻度偏差可继续；具体容差在试调与试玩后配置。明显漏掉关键原料时提示回到工作台调整。玩家也能主动选择跳过操作，不被一杯酒永久卡住。

“跳过介绍”“跳过制作”“重做教学杯”含义不同：前者仍制作；第二项不伪造实际杯子与完美评分；第三项清空本次教学状态并按独立教学补给规则重开。

## 五 教学资源与营业状态隔离

建议添加明确的 tutorial 上下文，不能借研发模式给正常库存无限退款。

- 教学原料使用独立有限补给记录；补给不足时可重置教学包，不影响玩家已购买原料。
- 教学会话不产生销售、不占顾客订单、不增加满意招待次数，也不触发米洛等角色的章节进度。
- 教学材料、未交付成品不可通过回主菜单出售或转成无限免费库存。
- 保存节点、会话 ID、配方版本、容器内容与已完成动作一起恢复；回到页面不重新发一包原料。
- 教学结束授予配方时使用一次性领取记录。是否解锁“回响”、是否自动上架单独配置；建议解锁后让玩家自行上架。
- 正式营业沿用当前营业时钟与接客服务。序章翻牌可以表现黄昏，但不得绕过系统配置，在未到营业时刻时硬生成正在营业的顾客订单。
- 旧存档不强制重走序章；提供独立回看或练习入口，不清空角色故事、手帐和小游戏奖励。

建议存储字段包括 opening_version、node_id、choice_flags、tutorial_session_id、tutorial_recipe_version、tutorial_step、tutorial_status、reward_claimed。它们是待实现接口建议，不代表现有项目已含这些字段。

## 六 验收方式

从新档进入时可以完整走到第一次接客；中途退出可恢复；两种对话选择都能继续；漏料和跳过不会得到假的成功评价；取消与转移不重复扣料；重试不刷金币或配方；正常库存不受教学包重置影响；文字、高光和目标刻度引用同一份配方；旧档原有工作台、自由调酒、角色剧情和小游戏均可继续。

具体计时、容差、冰量、资源数量与配方成本在配方试饮、UI 试玩和现有库存数据核对后定稿。本轮不向正式配置写入这些数值。
