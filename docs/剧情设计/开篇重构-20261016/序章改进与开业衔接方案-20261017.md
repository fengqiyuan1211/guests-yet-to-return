# 序章改进与开业衔接方案

日期：2026-10-17。前五项已经接入；第六项以下全部属于**建议，尚未接入游戏，待确认**。

本日交互修复：历史关闭后焦点曾停在历史按钮，Godot 会把空格视为激活该按钮。现在序章在控件处理前接管空格的按下与松开，空格只走剧情继续逻辑；H 专门开关历史，Esc 关闭弹窗。保留鼠标点击及 Tab / Enter 操作。补齐工作台量取、重做、成品依据等弹窗的点击按钮；教程的空格键图示也已改成可点击的停止／出杯按钮。通过实际 Viewport 键盘、鼠标事件回归：序章与教程 383 项、工作台 37 项，共 420 项通过，另通过旧档保留与首次启动恢复检查。

## 一、前五项实际改动

### 1. 历史对话

右上角新增“历史对话 H”。点击或按 H 打开，滚轮翻阅；Esc / H 关闭，回到原句原来的打字位置。打开时暂停对白打字，空格不会穿透到剧情里。历史窗不会触发节点音效、提交选择或推进故事。

记录包括已出现的对白、玩家选中的回答及对应回应、确实点击读过的邮件全文。尚未出现的节点、没选的分支和未读邮件正文不会提前显示。相同节点只记录一次；回看序章用独立记录，退出后恢复正式旅程。

历史随序章存档保存，退出重启仍可看。没有另建正式客人手帐条目，避免把序章旁白混入经营阶段的来客记录。

### 2. 报幕可读性

左上角章节与场景名称加深色半透明底框、细金边和内边距。宽度随文字调整，保留原有暖色手绘背景，不遮住右上角的历史、跳过和返回按钮。

### 3. 分场景音乐和音效

| 段落 | 声音设计 |
| --- | --- |
| 公寓独处、离职回忆、等待回信 | 新增原创稀疏键盘合成曲 quiet-room，音符间留空，突出内心独白 |
| 年轻时办公室相处 | 使用项目已有 Bossa Antigua，带一点轻松的节拍，与离职段形成对比 |
| 城市酒吧、Last Word 与回响 | 使用项目已有夜间爵士，命名后的碰杯有短促玻璃声 |
| 海路、抵岛、门口 | 回到用户选定的 Laura，叠加低音量海浪；离开海边后海浪淡出 |
| 同事一起笑、醉后回忆 | 两处短而轻的真实笑声，不循环，不做夸张冷笑 |
| 两次新邮件抵达 | 新增原创短双音提示，不使用突兀的星光敲击声 |
| 收拾纸箱 | 低音量干燥摩擦拟音，复用项目已有素材 |

场景音乐共用现有 Music 总线，3.5 秒交叉淡化，不为每句对白重启音乐。环境声和节点音效受 SFX 控制。本次没有改动玩家的音量偏好。

音效绑定节点 ID；同一句重新刷新、选择完成后重绘、翻阅历史不会重复触发。快速进入下一句会停止上一句的短音效，防止叠出一串笑声。切离游戏窗口停止短音效、暂停海浪，返回后恢复环境声。

笑声来源为 jodybruchon 的 [Voices - male laughter - mild chuckles.wav](https://freesound.org/people/jodybruchon/sounds/459455/)，CC0；来源、处理和校验值记录在 `assets/audio/opening/story-sources.json`。原有配乐授权继续见 `assets/audio/music/credits.json`。

### 4. 命名时说出英文

我：“回响。Echo World。不是给 Last Word 换一个词——是喝完以后，那些以为过去了的声音，又回到你身边。”

那位客人：“Echo World……回响的世界。名字挺大，这杯倒没有急着把话说满。”

我：“那就先把这四个字记下来。好不好，等下一次喝的时候再说。”

正式名称继续保持“回响 / Echo World”。不是把 Echo World 当成“回响”的标准英译，而是角色为这一杯取的名字；不改回 Echo Word，也不新建另一份酒谱。

### 5. 回复邮件以后，留出等待与期待

两个选择均改成“我发出邮件”，不再在选择回应里立即出现老管家的回信。随后顺序如下：

1. 主角假装只是随手问问，认为一封信不会解决现实困难。
2. 起身倒水，回来时房间暗了一些，画面仍在“已发送”。这是叙事时间流逝，不强迫玩家真的等几分钟。
3. 自嘲：酒后的约定和陌生酒馆，怎么看都不像以前会签字的方案。
4. 忍不住反复刷新；开始想到房间潮不潮、带什么衣服、见面说什么。
5. 承认自己已经在盼，盼明天有一件值得出门去做的事。
6. 心声：“也许我真的需要这封回信，拉我一把。哪怕先让我离开这张桌子……算是救我一命吧。”
7. 邮件提示音响起；他差点碰翻杯子。出现“回复：椅子还在，您慢慢来”的新收件通知，玩家点开阅读。
8. 管家说明自己刚收好外面的椅子，才看到邮件；附路线、船班和待核对的交接清单，提醒带外套，不催主角立刻作决定。
9. 读完才进入“几天后核对交接安排、订船票”，接已有海路段。

这一段的重点是主角重新产生期待。管家提供的是可执行的下一步，没有许诺替主角解决所有问题。

- `scripts/opening_story.gd`：历史入口、报幕底框、模态交互和节点声音调度。

序章内部 `story_version` 升到 3，外层存档版本仍为 1。新增冻结的 `story-v2-index.json`，搭配旧的 v1 索引迁移；旧玩家根据原来的稳定节点 ID 恢复，不因中间插入台词而跳到别的剧情。

旧版本没有逐句历史，因此历史迁移以旧脚本截至存档位置的内容重建，明确不加入这次插入但旧玩家没看过的句子。旧存档的选择和已读邮件保留。损坏或 ID 与位置不一致的存档拒绝猜测，不覆盖原文件。

正常仓库、金币、客人进度及工作台半成品不因看剧情而改变。回看仍使用独立序章存档；本次第六点没有改变教程结束后的正式开业流程。

验证：Godot 实际渲染的序章与教程集成测试 360 项通过；另通过旧档入口保留、首次打开标题后重启两组检查。覆盖历史禁止越界、模态空格阻断、选择与邮件保存、v1/v2 迁移、音效不重复、每个节点的音频资源、实际教学调酒和回看隔离。截图位于同目录 `20261017实机截图`。

## 三、第六点：从“做出回响”走到“真正开门”（建议，未实现）

本节保留最初提案。加入商店老板娘、好感度与线索教学后的完整扩展稿见[《第六部分剧情与新手引导详细方案》](./第六部分剧情与新手引导详细方案-商店与关系线索.md)。扩展稿同样尚未接入游戏。

### 核心方向

建议补一段约 3–5 分钟的轻剧情和准备操作，时间只是演出估计。主角的变化应当通过几件小事发生：接受今天这杯酒的结果，给送货的人倒水，签自己的名字，为今晚备好一款能卖的酒，最后翻转营业牌。

快递员保留为**独立的投递员角色**，名字和完整外形待定。老稿把他留在后续建议中，目前代码的正式首客是米洛；建议让投递员在开业前办送货事项，米洛仍是开业后的第一位点单客人。这样不用改写米洛现有来访、口味或小游戏解锁进度。

### A. 这杯是今天的味道

镜头：吧台近景，呈现玩家实际完成的回响；不强制替换成永远完美的插画。杯边与管家的衣袖进入画面，不出现具体人脸。

管家根据实际结果只说一条，例如：

| 实际结果 | 建议台词 |
| --- | --- |
| 接近配方且操作稳定 | “香气回来了。您尝尝，是不是记得的那个味道？” |
| 明显偏酸 | “青柠先出来了。先记下这一杯，下一杯就知道往哪儿调。” |
| 明显偏甜 | “甜味留得久了些。两种利口酒，咱们下一杯慢一点量。” |
| 其他偏差 | “和纸上那杯不一样。差在哪儿，咱们已经记下来了。” |
| 跳过教学 | “步骤先留着。哪天想练，我们再开一杯。” |

我：“记忆里好像没这么难。”

老管家：“记忆里，通常不用洗量酒器。”

我：“……也是。”

老管家：“他留的是配方。今天倒多少，还是得您自己看着。”

教学杯保留自己的单杯记录，不当作销售订单，不自动收钱。跳过教程不出现喝酒或成品特写。

### B. 敲门的是投递员

音效：两下木门轻敲、包裹落在木台面的声音、纸张摩擦。音乐继续安静，直到备料时才略微抬起节拍。

门外：“有人吗？送东西的。我看灯亮了。”

我：“还没……我们还没开门。”

投递员：“没事，我也不是来点单。只是这回，能让收件人自己签字了？”

老管家：“以前几次都是我代收。这份交接账册，一直替您留着。”

动作：包裹放下，标签和签收处亮起。点击或按空格签收，不要求真的用鼠标写汉字。

我 · 心声：“收件人那一栏，是我的名字。不是职位，也不是哪一个项目的负责人。”

投递员：“那以后送这里的东西，我就找您了。”

我：“……好。”

包裹内容建议是已整理的账册、旧酒单和空白收货单，属于剧情物件，**不凭空往仓库塞一批免费原料**。这让投递员自然承担日后采购到货的叙事接口，但本次不顺手新增配送计时系统。

### C. 给赶路的人一杯水

投递员揉着肩膀：“我在门口歇一会儿就走，下一家还等着。”

我：“椅子就在外面。要不要喝点水？”

投递员：“好。常温的就行，我还得赶路。”

动作：一次点击递水，使用叙事动作；不强迫再制作一杯酒，也不涉及饮酒后驾船等多余设定。

投递员：“以前走这条路，总会在这儿停一下。没想到今天又亮灯了。”

我：“我还在学。”

投递员：“那我下回来，看看您学得怎么样。”

我 · 心声：“我本来以为，开店得先准备一句像样的欢迎。原来第一句话，只是‘喝点水吗’。”

这就是主角第一次主动照顾来人。门口那把“谁累了都能坐”的椅子也得到实际用途。

### D. 今晚先备一款

老管家：“今晚卖什么，先听您的。不过纸上有的，架子上未必有。”

我：“先看库存。”

建议只引导一次“仓库→商店（若缺料）→营业酒单”，不是强迫所有人重复买同一批材料。

1. 查真实仓库；已有存货的玩家直接进入酒单选择。
2. 缺料时清楚列出缺少的 SKU、数量和购买价格。跳到既有商店；玩家实际购买才扣款、补库存。
3. 酒单至少选一款当前能够制作的酒；建议突出“回响 / Echo World”，也允许选已有其他酒款。
4. 图鉴解锁不等于自动上架，仍由玩家确认加入营业酒单。
5. 若正式经济配置无法负担任何一款，提供“先看准备说明／稍后开门”，不能为了推进故事暗扣到负数，也不能偷偷发测试金币。正式开局预算和首批备料规则须另行确认。

这里只使用既有仓库、商店、酒单数据，不增加独立的“剧情库存”。采购演示在回看模式里应为只读说明或隔离练习，绝不能花掉玩家正式存档里的钱。

### E. 这次，我在门里面

镜头：门内看向黄昏的海港；帘角、门灯和营业牌少量运动。继续无脸手绘方向。

老管家：“今天就开这一会儿？”

我：“先开这一会儿。”

老管家：“那牌子，您来翻吧。”

操作：营业牌轻微发亮，点击、拖动或空格都能翻转；灯亮，海浪逐渐退到大厅环境声后面。

我 · 心声：“过去，我总等着有人告诉我，下一步该做什么。这一次，门在我手里。”

我：“进来吧。”

门铃轻响，接米洛已有的第一句：“这儿有人坐吗？我在外头转了半天，想找个地方歇歇脚。”

从这句开始交回现有正式接待流程。主角不再连续长篇独白，让玩家真正开始经营。

### 确认后建议的接入边界

- 新增单独的教学后剧情阶段和稳定节点 ID，进度与经营开业标记分开保存；读档返回未完成步骤。
- 教学评价读实际单杯结果，分支有优先级和兜底；研发评分系数无需为这段剧情另造一套。
- 签收、翻牌、首客到访都使用幂等标记；反复点击、重开页面不会重复发东西或生成两个米洛。
- 回看结束回标题，正式旅程与库存保持原样；跳过这段不伪造采购或销售。
- 已经营业的旧存档不强插教程；提供独立回看入口。
- 投递员本次仅承担这段短剧情，不默认解锁好感、小游戏或整条支线；这些可在以后扩展。

### 请确认的主方向

建议采用“实际回响结果→投递员送交接账册→递水与门口椅子→按库存备一款酒→亲手翻牌→米洛首单”。若认可，再把本节制作成正式节点、CG 叠层和交互；当前游戏仍保持原有的教学结束接开门流程。
