# 第六部分：从一杯回响，到酒馆第一次开门

日期：2026-10-17。状态：**已确认方向，首版主流程已接入 Godot。**

本文件保留设计讨论时的提案原文；当前完成范围、实际配置、测试与未完成项，以[第六部分实现说明与验收](第六部分实现说明与验收-20261017.md)为准，不应把下文所有建议当成已实现功能。

本稿扩展《序章改进与开业衔接方案》的第六部分。下文新增的对白、老板娘设定、关系机制、线索、界面和后台字段均为**建议**；标注“现有”的内容来自当前项目。时间、关系数值、门槛与经济配置不作为定稿。

## 1. 这一段要带给玩家什么

建议把这一段命名为 **“先把今晚的灯点起来”**。

刚刚完成“回响 / Echo World”的主角，还没有突然变成成熟的酒馆老板。他先接住今天这杯酒的结果，接下一份送到自己名下的包裹，去认识以后会经常打交道的老板娘，最后亲手把营业牌翻过来。

玩家通过这段经历理解四件事：

1. **调酒有实际成本。** 教学材料与正式库存不同；营业会消耗原料，不够就去商店补货。
2. **商店里也是一个人。** 老板娘提供物资，也记得这座港口和酒馆过去的一些事。
3. **做得好与合人口味有区别。** 客人有当下的要求，一杯技术上不错的酒，也可能不适合他今天的心情。
4. **熟悉是慢慢发生的。** 好感度和故事经历会带来新的对白、线索或邀请；这些内容不等同于多卖几杯酒。

建议的完整顺序：

**实际回响成品 → 投递员与门口的椅子 → 查看库存、准备酒单 → 港口商店与老板娘 → 翻转营业牌 → 米洛第一次正式招待 → 手帐中的关系与未解线索 → 自由经营。**

新增对白与轻操作的演出时间建议控制在约 6–9 分钟；米洛已有的第一章与玩家实际调酒时间另计。允许快速读完、跳过演出和暂时离开，不要求现实等待。

## 2. 与当前游戏对齐的边界

| 内容 | 当前实际情况 | 本稿建议 |
| --- | --- | --- |
| 回响 | 已有官方配方；使用午夜蓝草本酒，钴蓝酒体；教学使用独立材料 | 保持名称、材料、颜色和实际制作结果，不改回蓝橙方案 |
| 教程结尾 | 当前是教学完成后的简单结尾，再进入正式酒馆 | 补充本稿的准备与开门过程 |
| 商店 | 已有白发老板娘、货架、商品规格、购买数量、金额和真实入库 | 复用界面，加首次见面对白与操作引导 |
| 老板娘 | 有立绘及三句商店闲话，尚无正式姓名、完整支线 | 补充人物性格；本稿暂称“老板娘”，不擅自定名 |
| 手帐 | 已有客人资料、历史对白、饮酒与招待记录、小游戏入口 | 增加关系摘要及已知线索；仍叫“手帐”，不恢复“评价”入口 |
| 长期好感度 | 尚无统一的好感度数值系统 | 建议新增统一关系记录，先让变化理由和阶段清楚可读 |
| 小游戏 | 现有条件按章节及部分角色的满意招待次数判断 | 保留现有解锁节奏；教程不强制展示、进入或通关小游戏 |

米洛仍是正式开业后的第一位点单客人。投递员只承担开业前的短剧情，不替换米洛，不用这一小段把他升级成新的常驻客人系统。

## 3. 逐场剧情、操作与反馈

### 第一场：今天这杯，就从今天记起

**场景目的：** 收束调酒教学，让主角接受不完美，也提醒玩家成品反映自己的实际操作。

**画面建议：** 复用吧台，展示实际杯型、酒量与钴蓝酒液。管家只出现袖口或画外音。不要用一张永远满杯、永远完美的酒图替换玩家成品。

管家根据实际结果说一句短评；只选一条，不连续罗列缺点：

| 条件 | 对白草案 |
| --- | --- |
| 接近配方，操作稳定 | 老管家：“香气回来了。您尝尝，是不是记得的那个味道？” |
| 明显偏酸 | 老管家：“青柠先出来了。把这次的量记下，下一杯就知道往哪儿调。” |
| 明显偏甜 | 老管家：“甜味停得久了些。两种利口酒，下次可以再量稳一点。” |
| 其他偏差 | 老管家：“和纸上那杯不一样。差在哪里，咱们已经记下来了。” |
| 跳过调酒教学 | 老管家：“步骤先留着。哪天想练，我们再开一杯。” |

完整制作后的接续对白建议：

> 我：“记忆里好像没这么难。”  
> 老管家：“记忆里，通常不用洗量酒器。”  
> 我：“……也是。”  
> 老管家：“他留的是配方。今天倒多少，还是得您自己看着。”

短暂停顿，主角看一眼纸上的“回响 / Echo World”，门外响起两下敲门声。

**交互：** 点击“收好这次记录 / 空格”继续。结果详情可以查看，但不要求先读完全部评分。

**规则：** 教学杯不生成销售收入，不结算成米洛的订单，不增加任何客人的满意招待次数。跳过时使用专用对白，不假装玩家已经做出或喝过这杯酒。

### 第二场：收件人是我

**场景目的：** 承接前面的邮件与交接，让“接手酒馆”成为一次玩家亲自完成的小动作。

**画面建议：** 门口逆光、投递员的肩背或袖口、放到木台上的包裹；镜头不出现具体人脸。

> 投递员：“有人吗？送东西的。我看灯亮了。”  
> 我：“还没……我们还没开门。”  
> 投递员：“没事，我也不是来点单。只是这回，能让收件人自己签字了？”  
> 老管家：“之前是我代收。整理好的账册，今天一起送来了。”

包裹标签与签收处轻亮。玩家点击或按空格签收；不要求鼠标写字。

> 我 · 心声：“收件人那一栏，是我的名字。不是职位，也不是哪一个项目的负责人。”  
> 投递员：“那以后送这里的东西，我就找您了。”  
> 我：“……好。”

包裹内容建议为账册、旧酒单和空白收货单。它们是剧情物件，不计入可销售原料，也不附赠一套隐藏的测试资金。

投递员揉揉肩膀，看向门口的椅子：

> 投递员：“我在门口歇一会儿就走，下一家还等着。”  
> 我：“椅子就在外面。要不要喝点水？”  
> 投递员：“好。常温的就行。”

玩家点击“递一杯水 / 空格”，完成一个短动作。水不要求玩家重新走一遍工作台，也不生成正式售酒订单。

> 投递员：“以前走这条路，总会在这儿停一下。没想到今天又亮灯了。”  
> 我：“我还在学。”  
> 投递员：“那我下回来，看看您学得怎么样。”  
> 我 · 心声：“我本来以为，开店得先准备一句像样的欢迎。原来第一句话，只是‘喝点水吗’。”

**叙事作用：** 门口那把“累了就能坐”的椅子得到实际用途。主角第一次主动照顾来人，比一段开业宣言更自然。

### 第三场：纸上的配方，不等于架上的存货

**场景目的：** 把独立教学自然过渡到真实库存与经营。

> 老管家：“今晚卖什么，先听您的。不过纸上有的，架子上未必有。”  
> 我：“先看库存？”  
> 老管家：“对。刚才练习那份单独备着，往后营业，就得记这本账了。”

**操作顺序建议：**

1. 高亮现有仓库入口，点击或使用对应快捷键打开。
2. 只提示一次：“这里是正式库存。取出材料开始制作后，就会实际消耗。”
3. 查看已有、已解锁的酒款，玩家挑今晚准备售卖的酒；回响可以选，但不强制上架。
4. 根据真实配方及库存，显示所选酒款还缺什么。杯具要求、冰及必需装饰也参与可制作判断，不能只查液体。
5. 有缺料，提供“去商店补货”；材料已足够，则提供“去认识老板娘 / 已备齐，继续”。

这里的酒款选择先作为准备目标。真正加入营业酒单仍要由玩家确认；解锁酒谱、列入准备清单、确认上架是三个不同动作。

**玩家可见的缺料卡示意，数量全部由当前存档生成：**

| 原料 | 当前库存 | 本次准备所需 | 还缺 |
| --- | --- | --- | --- |
| 当前所选酒的材料 | 实际数量与单位 | 按配方和计划杯数计算 | 两者差额，最低为零 |

教学初版建议只准备能做一杯的最低物资，再由玩家自行加购；不把某种瓶装容量、整果换算或备料杯数写死在对白里。若考虑容错备料，应在清单中明确显示，不能暗扣或暗加。

**新开局保障建议：** 正式开局资金与可购买物资应经过数据校验，保证至少能负担一款已解锁酒的完整备料。具体预算待经济配置确认，不能用当前测试用的 300000 金币充当正式设计。旧档或玩家已经花光钱时，保留返回经营、选择别的酒和稍后准备的路径；任何援助或赊账都要另行设计，不能临时偷偷补钱。

### 第四场：港口商店，先认识老板娘

**场景目的：** 教会购买、入库与余量，同时把商店从“补给菜单”变成日后愿意再来的地方。

#### 4.1 人物建议

沿用现有白发老板娘立绘。正式姓名尚未确定，本轮用“老板娘”即可。

- **日常身份：** 港口供货店的经营者，熟悉到港货物和本地店家的需要。
- **性格：** 利落，会算账，有分寸的善意。她会提醒新手别一次进太多货，不靠讲大道理塑造亲切。
- **与前任经营者的关系：** 建议设为过去有正常供货往来。知道一些日常琐事，不能因此推导她知道所有真相。
- **与主角的关系起点：** 先是新客户，再逐渐成为能聊几句的人。买得多不等于关系好。
- **行为细节：** 对账时敲一下账本边；包瓶子时先垫纸；聊到旧事时动作短暂停顿，再把商品摆正。
- **支线潜力：** 她自己的经营压力、记得的旧客、留着的单据。后续不能永远只承担给主角讲别人故事的工具人职责。

她不是米洛的妹妹莉娅；项目中莉娅已有明确身份，不复用这个名字。

#### 4.2 初次见面对白

开门铃轻响，进入现有商店场景。主角带着包裹里的旧账册来核对采购。

> 老板娘：“船刚靠岸，今天的货都在这儿了。要买什么？”  
> 我：“我接了那边的酒馆。今天……想先开一会儿。”  
> 老板娘：“原来那盏灯是你点的。”  
> 我：“是不是该先把架子摆满？”  
> 老板娘：“先别。你今晚想做什么，就先备什么。架子满不满，客人未必在意；酒里少了什么，一口就知道。”

若玩家已经备齐材料，改为：

> 我：“材料已经清点过了。管家让我来认认门。”  
> 老板娘：“那就不急着买。先看看，缺了再来。”

这个分支同样完成认识老板娘，不强制为了教程浪费钱。

准备阶段建议暂停正式营业计时与客人等待计时；翻牌后再接回正常营业时钟。阅读说明不应消耗尚未开始的一晚营业时间。画面光照继续读取同一时间源，不另造商店或工作台自己的时钟。

#### 4.3 采购教程：只教四件事

复用当前“原酒 / 配料 / 装饰品”分类，不临时加一套覆盖现有商店的全新商场 UI。

| 玩家动作 | 指引表现 | 要理解的事 |
| --- | --- | --- |
| 点击缺少的商品 | 对应商品边框缓慢亮起，动态光标指向商品 | 商店卖的是什么 |
| 看下方采购单 | 光标移向规格、库存、数量、总价所在区域 | 一瓶或一包有多少；买几份花多少钱 |
| 点击购买，或在购买明确被选中时按空格 | 成功后物品轻移、货币与库存反馈；商品材质音效沿用现有系统 | 购买真实扣钱、真实入库 |
| 返回检查 | 展示该商品“购买前 → 购买后”的余量；不足清单重新计算 | 工作台与仓库使用同一份库存 |

提示文案建议：

> “买入的是整瓶或整包，调酒按实际用量消耗。没用完的会留在仓库。”

若商品资料确实支持当前计算，再显示：

> “按这份配方，该原料目前约可供 X 杯使用。”

必须写“该原料”，不能把某一瓶的可用杯数冒充整款酒的可售杯数。整款酒的可制作数量应取所有必需材料的限制，并考虑当前配置是否完整。

买对东西后，老板娘补一句：

> 老板娘：“给你收好了。价钱和份量都写着，回去照着点一遍。下回缺什么，再来找我。”

买错商品不当成教程失败，也不自动退款。保留商品，更新真正缺少的项目，再提示继续选择。余额不足则正常显示原因，并允许更换备料目标。

#### 4.4 一句没有说完的话

采购完成或看完商品准备离开时，老板娘注意到旧账册。**这段也会在不购物的认识分支发生，不与花钱绑定。**

> 老板娘：“这本账也交给你了？”  
> 我：“刚收到。怎么了？”  
> 老板娘：“以前的送货单，我这儿还有几张。”  
> 我：“还有没结的账？”  
> 老板娘：“账早结清了。有一张一直没舍得扔。”

她把手里的包装纸折好，停一下：

> 老板娘：“那张背面写的，不是买卖的事。今晚先忙开门吧，以后有空坐下来，再聊。”

提供两个语气选择，都不会导致永久错过：

- “好，等忙完我再来。” → 她点头：“先把今晚顾好。”
- “是跟酒馆有关的事吗？” → 她答：“有一点。也不全是酒馆的事。”

不要把第二项写成恶意追问，也不为正常好奇偷偷扣好感。真正的冒犯或失约如果以后会扣分，应有清晰语境。

“等忙完我再来”只是自然回应，不建立隐藏的限时任务；玩家晚几天回来不会因此被扣好感。

屏幕角落出现一次轻提示：**“手帐已记下：老板娘提起一张留下来的旧送货单。”** 玩家可以点开看，也可以继续走。此时只有听说，不能直接得到尚未看过的纸张或背面内容。

### 第五场：今晚先开这一会儿

回到酒馆，只检查真实准备状态，确认至少一款能够制作的酒已由玩家加入营业酒单。

> 老管家：“买齐了？”  
> 我：“先够今晚这一点。她说，不用急着把架子摆满。”  
> 老管家：“这话很像她会说的。”

若未购买而库存本来足够，换成“清点好了，先做这几样”，不伪造采购经历。

门口是黄昏海港。镜头从门内看出去，和主角最初抵达时从外面看酒馆形成呼应。

> 老管家：“今天就开这一会儿？”  
> 我：“先开这一会儿。”  
> 老管家：“那牌子，您来翻吧。”

**操作：** 营业牌轻晃并有柔和描边，动态光标示意翻转。拖动、直接点击或按当前提示的空格，都完成同一个动作。

灯亮、木牌轻响，海浪退到环境声后。背景时间沿用现有时段系统，不把当前已经是夜晚的存档突然改成黄昏。

> 我 · 心声：“过去，我总等着有人告诉我，下一步该做什么。这一次，门在我手里。”

门铃响起，接米洛已有的初见：

> 米洛：“这儿有人坐吗？我在外头转了半天，想找个地方歇歇脚。”

### 第六场：第一次做给一个具体的人

**场景目的：** 从“照配方练习”转向“听懂这个客人”。

保留米洛已有的自我介绍与第一章“封面上有我的名字”：他爱把旅途讲得精彩，给妹妹莉娅写信，却渐渐发现她也关心那些普通细节。不要为了教系统，让他突然替游戏念一段好感度说明。

他当前第一轮的口味文字是：

> “有橙子的香气就好，甜一点也行，别把酸味全盖住。不要奶制品。”

这句话需要醒目地记录在订单与手帐中。后续剧情改变口味时，使用当次来访的要求，不把第一轮口味写死成永久偏好。

**首单操作引导建议：**

1. 读到口味后，第一次轻亮“本次要求”，提醒玩家有硬性禁忌。
2. 点击“前往调酒台”先到已有酒单页，左侧选酒、右侧看属性；返回入口清楚保留。
3. 给出可制作且不触碰奶制品禁忌的候选。橙香只是匹配依据之一，不把不含橙味直接当成订单非法。
4. 不固定选“回响”，不偷偷修改它的属性去迎合米洛。已有酒款中能做到的匹配程度应如实显示；未满足的需求也应可见。
5. 进工作台后沿用之前学到的操作，只在首次卡住或玩家主动求助时增强提示，不完整重播一次所有工具教学。
6. 出杯后的品质、满意度、钱款均读实际结果，成功交付和结算后再写入这一轮记录。

若当前酒单没有高匹配酒款，允许使用可做的候选，也可去采购、调整酒单或采用已经开放的自由制作方式；不强迫此处再学研发模块。验收时要单独检查正式新开局至少有一条可负担、不触禁忌的首单路径，不能靠临时改客人偏好解决。

**实际反应示例，只在对应事实成立时使用：**

| 结果 | 建议回应 | 关系反馈 |
| --- | --- | --- |
| 符合当次要求 | 米洛：“橙香留着，酸味也没丢。你真把刚才那几句话听进去了。” | 可记录“记住了这次口味”，按正式规则增加关系值 |
| 无禁忌但口味一般 | 米洛：“跟我想的有点不一样，不过我也正想找个地方坐坐。” | 保留初识、正常记录满意度；不硬写“非常满意” |
| 明显不合口味 | 米洛：“今天可能喝不惯这个味道。下次给我清爽一点的吧。” | 如实反馈、允许之后改善；不锁住后续所有故事 |
| 触及奶制品禁忌 | 米洛：“这里有奶吗？抱歉，这杯我不能喝。” | 优先走既有禁忌处理；不演出喝下、不额外伪造销售与赞许 |

这些新增短句不能替换他原有章节中的关键事实，也不把“喝完一杯”擅自等同于“完成一章”。章节完成仍走现有对话确认流程。

### 第七场：手帐记住的是人

**触发：** 第一次实际招待处理完成后，弹一个小型角标“手帐更新”，点击打开；提示不要遮住客人的反应。若玩家暂时不看，入口保留温和标记，可稍后补看。

**首次关系教学所展示的内容建议：**

```text
米洛                          关系：初识

今天记住的事
  给妹妹莉娅写信；第一次把自己的名字印在地图封面上。

本次口味
  橙香，略甜，保留酸味；不喝奶制品。

这次招待
  实际酒名 / 实际属性 / 品质 / 满意度 / 实际付款

关系变化
  已互相介绍。
  若确实成立：记住了他的口味。
```

不显示玩家尚未读到的身世，不伪造喝完或结算的记录；示意中的事实也必须以实际已读节点为准。

管家在客人离开、或对白自然停顿处说：

> 老管家：“刚才他说的那些，您都记下了？”  
> 我：“怕下次又问一遍。”  
> 老管家：“记不全也不要紧。人愿意再来，话就有机会慢慢说。”

此时只给一次明确的系统说明：

> **“认真招待、回应对话，可能提升好感度。随着关系加深、相关故事推进，人物可能愿意告诉你更多：新的对话、线索，或一次特别的邀请。每个人的条件都不同。”**

“可能”很重要：不能承诺每杯好酒都立刻发线索，也不能让人误以为所有内容只看一个数值。

手帐侧边同时可看到老板娘已记下的那句“旧送货单”。玩家如果点开，显示：

```text
老板娘                        关系：初识

未完的话 · 留下来的旧送货单
已知：她保留过一张与酒馆有关的送货单。
她说账早已结清，留着它与价钱无关。
还不知道：那张纸的背面写了什么。

下次可以做的事：有空再去和她聊聊。
```

这已经足够让玩家理解“人物关系会带出隐藏内容”。教程里不播放任何小游戏，不要求完成小游戏才算学会经营。

### 第八场：把操作权交还给玩家

> 我 · 心声：“灯点起来之后，事情倒没有一下子变好。只是下一次有人敲门，我知道该先做什么了。”

底部出现一次短提示：“你可以继续接待，也可以查看手帐、补充原料，或整理酒单。”

随后退出强制教程状态。只保留玩家主动打开的帮助，不安排连串弹窗继续解释未使用的功能。

## 4. 好感度和线索，建议怎样判断

### 4.1 四套数据必须分开

| 系统 | 回答的问题 | 主要依据 | 不应该发生的事 |
| --- | --- | --- | --- |
| 成品品质 | 这一杯做得怎么样？ | 实际原料、用量、步骤、技法及成品状态 | 为了剧情把失误杯强改成完美 |
| 本次满意度 | 这个人今天喜不喜欢？ | 当次口味、硬性禁忌、实际出品、现有评价规则 | 把高品质自动等同于人人喜欢 |
| 长期好感度／关系 | 他愿意与你熟悉到什么程度？ | 有意义的交流、招待、选择、承诺与事件 | 每买一瓶酒、点一次按钮就涨好感 |
| 线索进度 | 玩家实际知道了什么？ | 已发生事件、已见物件、已读对话及验证结果 | 好感一满就把没见过的秘密写进手帐 |

玩家界面可以叫“好感度”，人物页用“关系”作为自然表述。它涵盖信任和熟悉，不默认代表恋爱。

### 4.2 建议的关系阶段

建议先用 **初识 → 熟悉 → 信任 → 深交** 四个阶段；名字、分值及门槛都待定。

- **初识：** 真正见过面、互相介绍；这可以在首见完成，不需要先做出高分酒。
- **熟悉：** 有过实质交流，开始记住一些生活细节。
- **信任：** 有足够共同经历，愿意谈较私人的事。
- **深交：** 人物某一阶段的关系结果；不能等同于全部故事已经讲完。

首版界面建议显示阶段和最近一次变化原因，暂不强制显示“37/100”。后台仍可保留可调整的关系值和规则版本；如果以后需要明确数值，再增加显示选项。

首次对话产生“初识”，不等于立刻得到“大幅好感提升”。只有实际行为符合配置，才显示具体的提升反馈。

### 4.3 哪些行为可以影响关系

| 行为 | 建议处理 |
| --- | --- |
| 真正完成第一次互相介绍 | 记录认识标记，建立人物页；不当成刷分事件 |
| 正式来访中，做出符合当次需求的酒 | 根据既有满意度与关系配置给出一次增量 |
| 认真回应人物的处境 | 有明确剧情语义时写关系事件；不要求所有选择都有隐藏优劣 |
| 尊重拒绝、记得已约定的事 | 根据对应事件给予变化或开启后续对话资格 |
| 反复点击肖像、翻历史、重复读同一句 | 不增加 |
| 商店大量购物 | 不按花钱金额换算好感 |
| 自由调酒、教学练习、研发试调 | 不冒充正式客人招待 |
| 重做、重复交付、读档重试结算 | 不重复增加；相同事件只记一次 |
| 明确冒犯或失约 | 可有负向变化，但必须有可理解的前因后果和后续修复机会 |

关系计算建议采用“已确认事件的变化量累积”，而不是直接把累计满意度当作好感度。事件权重、上限、重复招待收益衰减及负面后果均待配置，不在本次文本中写死。

### 4.4 线索出现的三个时刻

1. **留下话头。** 玩家听到“有张旧送货单”。手帐只记这句话。
2. **获得谈论资格。** 好感度达到该线索配置的要求，且完成相关故事前提；商店出现可选的“那张送货单……”话题。
3. **真正看见或听见。** 玩家选择该话题，读到对应内容或查看纸张之后，才更新线索正文。

资格达到不自动弹出剧透 CG，不强行打断正在购物或调酒的操作。玩家可以稍后再看，不因暂时离开而失去内容。

建议规则可表达为：

```text
该话题可出现 = 已认识人物
             且满足此线索独立配置的关系条件
             且满足相关剧情／物件前提
             且尚未完成此话题

手帐获得新证据 = 玩家实际触发并读到该证据
```

初见话头可以没有关系门槛；较私人的内容再配置门槛。主线必需信息不能只有一个很高的好感入口，否则一个普通失误就可能让玩家无法推进。

### 4.5 老板娘线索的后续走向示例

以下是可扩展方向，不要求在新手段实现，也不作为已经确定的世界真相。

建议后续关系推进后，老板娘拿出那张单子。正面的货款已经结清，背面却有一句：**“留到风停。”**

> 我：“留什么？”  
> 老板娘：“这就是我一直没舍得扔的原因。那天他没说清，我也以为，总还有机会再问。”

这个疑问可以引向“前任经营者替谁留过一杯酒／一次相见”，也可以先带出老板娘自己的遗憾。具体对象、时间和最终解释留待主线核对，不在这张单子上提前宣布死亡、失踪或阴谋。

后续还可以让不同人物提供不同证据，但不能为了显得复杂，让所有客人都恰好知道同一个大秘密。米洛的地图、老霍克的往事和艾达的时间困境仍有独立的人生重心。

### 4.6 保留现有小游戏节奏

现有正式条件保持：

| 人物 | 现有条件 | 本方案处理 |
| --- | --- | --- |
| 米洛 | 完成第 2 轮剧情，不额外要求满意招待 | 不加新的好感度门槛 |
| 老霍克 | 完成第 3 轮剧情，不额外要求满意招待 | 不加新的好感度门槛 |
| 艾达 | 第 5 轮剧情与 2 次满意招待 | 保留，除非另外确认调整 |
| 小线 | 原有五章与五杯评分流程 | 保留 |

这里的“轮”是已完成剧情章节，不是喝酒杯数。演示入口也不等同于正式剧情解锁。

以后一个角色的线索、支线、小游戏可以各有独立条件。例如第一次邀请来自第二章，较私人的旧事需要关系深入，第二个小游戏还需要发生另一个事件。它们不能全部捆在同一个“角色已解锁”开关上。

## 5. 画面、声音和提示的统一设计

### 5.1 视觉

继续当前暖色手绘、西部酒馆与海港风格。新增 CG 不出现清晰人物正脸，以物件、背影、衣袖和主角第一视角表达；不使用写实人像。常规商店页面继续复用已有老板娘立绘，正常客人页面沿用已有立绘，不额外改小线与黄色生物。

| 画面 | 建议新增／复用 | 动态细节 |
| --- | --- | --- |
| 实际回响成品 | 复用工作台成品渲染 | 杯中余波逐渐停止，光线轻移 |
| 包裹签收 | 门口背景加包裹、账册、签收单 | 包裹轻落、纸边微翘、签收后笔画出现 |
| 门口递水 | 椅子、杯水与袖口近景 | 衣角被海风轻推，杯落下后水面轻动 |
| 认识老板娘 | 复用港口商店、白发立绘和货架 | 包装纸、账本、视线或轻微姿态变化；不必新做大段动画 |
| 旧单话头 | 先只拍主角携带的账册 | 老板娘动作停顿，不提前把未解锁单据正文摆出来 |
| 第一次开门 | 复用门口海港，新增营业牌可交互层 | 木牌翻面、暖灯亮起，依实际时段显示光色 |
| 手帐更新 | 复用手帐纸页结构 | 铅笔划线、页角轻动，克制的更新标记 |

### 5.2 声音

- 回响收尾：保留舒缓音乐尾句，轻放杯与擦拭声。
- 投递员：两声轻敲门、包裹落木台、纸张摩擦；不配夸张任务完成音。
- 商店：使用现有舒缓、略热闹的港口方向配乐；海鸥、绳索、远处卸货声低音量点缀，不盖住对白。
- 商品：延续已有材质区分，玻璃瓶、纸包、叶片的声音不同。选择与购买成功各有反馈。
- 旧事话头：环境声稍收，音乐留白即可，不突然换阴森悬疑曲。
- 翻牌开门：木牌、门铃，渐入大厅 BGM。
- 手帐关系变化：极轻的落笔或翻页声。不用突兀的 bling，也不每加一点关系就响一次。

场景切换沿用现有音频总线、音量设置与交叉淡化。音乐不因一句对白重刷而从头播放；回看历史不重放节点音效。

### 5.3 交互与可读性

- 每一步只突出一个当前目标，复用动态光标、缓慢描边和局部亮度差。必要时提示移动到实际控件，不把整屏变成遮罩。
- 所有显示成按钮的控件都可直接点击；标注快捷键时，键盘与点击执行同一个动作。
- 空格优先执行当前明确提示的主动作。模态窗打开时由模态窗接管，不透传，不再次触发历史按钮焦点问题。
- 商店中空格只在明确的购买确认上下文使用，不能看对白时意外花钱；金额在按键前已经可见，不需要额外套三层确认框。
- 数量输入时按键由输入控件正确处理；选择选项时必须有可见选中状态，不能因上一步焦点残留替玩家决定。
- 历史对话继续支持 H、点击打开；Esc 或点击关闭。历史只读，不加关系、不发物品、不重复采购。
- 对话选项、返回、关闭、继续、翻牌均有清楚的鼠标入口。只给工具或确需解释的条目做悬停说明，不让每个按钮都弹空白或重复文字的小窗。
- 对手帐未读更新只用角标，除第一次轻引导外不频繁打断经营。

## 6. 后台衔接与开发拆分建议

本节是实施建议，字段名称为示意，不声称当前已存在这些服务。

### 6.1 剧情阶段与存档

建议给当前教学结束与正式经营之间增加独立的过渡阶段，内部用稳定步骤 ID：

| 建议步骤 ID | 完成依据 | 允许恢复的位置 |
| --- | --- | --- |
| `opening.cup_reflection` | 看完实际结果回应，或教学跳过分支 | 对应对白节点 |
| `opening.parcel_received` | 签收动作成功保存 | 签收后，不重新生成物件 |
| `opening.water_offered` | 递水动作结束 | 后续短对白 |
| `opening.prep_reviewed` | 查看实际库存与准备目标 | 仓库或备料清单 |
| `opening.merchant_met` | 完成互相认识的对白 | 商店当前状态 |
| `opening.shop_explained` | 已完成购买说明，或确认材料足够分支 | 不强制再次购买 |
| `opening.clue_seed_heard` | 实际读到旧送货单话头 | 对应手帐听说记录 |
| `opening.menu_ready` | 玩家确认酒单，且当前可制作校验通过 | 返回准备界面并重新校验库存 |
| `opening.sign_opened` | 翻牌保存成功 | 已营业，不再翻一次 |
| `opening.first_guest_queued` | 唯一首客事件写入 | 现有米洛来访会话 |
| `opening.relationship_intro_seen` | 真正看过关系说明；选择稍后只记录延后，不设为已读 | 手帐或正常经营；延后时保留一次待看提示 |

第一次正式结算应读取现有来访 ID 对应的结算结果，不能用“教程最后一步”再给米洛结算一次。

到翻牌开门时解除准备阶段的全局限制；关系介绍作为可稍后补看的独立引导，不让玩家因为未点手帐而无法接待其他客人。

**特别需要调整的现有接口：** 当前 `OpeningFlow.finish_opening()` 在结尾解锁回响并排入首客。若新流程要在开门前让玩家选择回响备料，须把“获得回响配方”的时点提到教学收束或准备阶段，采用同一个幂等解锁接口；不能等最终开门才解锁，也不能复制一份临时配方绕过。自动上架仍不允许。

### 6.2 现有系统继续负责原来的账

| 现有模块／文件 | 保持的职责 | 新段落只读取或调用什么 |
| --- | --- | --- |
| `OpeningFlow` / `data/opening/*` | 序章进度、回看与独立教学 | 新过渡步骤、对白、演出与恢复 |
| `Supplies.quote_purchase()` | 当前价格、包装数量、余额校验 | 展示真实采购信息 |
| `Supplies.purchase()` | 正式扣款、入库、购买事务恢复 | 调用成功后确认采购步骤；不再单独加一次库存 |
| `MenuCatalog` | 配方解锁、酒单等既有职责 | 解锁回响、玩家确认上架、读取可选酒款 |
| 工作台制作会话 | 取料、消耗、转移、单杯记录与成品 | 输出实际教学杯或正式订单杯 |
| `CustomerService` / 招待记录 | 正式订单、满意度、销售结算 | 读取真实结算结果和来访身份 |
| `StoryDialogue` | 章节、选择、已读对白 | 读取真正完成的节点及章节 |
| `GuestActivities` | 现有小游戏资格、邀请、奖励 | 保持原条件，不由关系教程另发一份邀请 |
| 手帐 | 汇总已知人物与经历 | 展示关系摘要与已知线索，不自行计算经济或解锁规则 |

商店购买成功信号可用于刷新引导，但不能当成唯一持久依据。重启后应根据交易记录与库存恢复引导，避免“买到了，教程却永远等一个已经错过的信号”。

### 6.3 关系数据建议

建议新增统一关系服务，由事件驱动，不把增减分散写在各个 UI 按钮里。

| 数据 | 建议关键字段 | 用途 |
| --- | --- | --- |
| 关系记录 | `person_id`、`met`、`value`、`stage`、`rule_version` | 存人物关系及计算规则版本 |
| 关系事件 | `event_id`、`person_id`、`source_type`、`source_id`、`reason`、`delta` | 记录变化原因，去重和恢复 |
| 话题配置 | `topic_id`、`person_id`、`requirements`、`entry_node` | 判断下次能聊什么 |
| 线索配置 | `clue_id`、`source_person_id`、`requirements`、`content_nodes` | 分开资格与实际内容 |
| 线索进度 | `clue_id`、`state`、`observed_node_ids`、`evidence_ids` | 区分听说、获得证据、后续确认 |

`person_id` 应支持客人和老板娘，不强迫老板娘先生成一张假饮酒订单才能有关系值。她的对白历史与线索仍能进入手帐，饮酒记录为空时自然不展示空的订单详情。

关系服务消费“已完成的领域事件”，例如已结算的招待、已完成的剧情选择；不消费未经保存的按钮点击。原始事件保存成功后，关系服务可以重放尚未处理的事件，并按事件 ID 去重。这样断电或切页时不会永久漏加，也不会重试双倍增加。

建议的去重范围：

- 首见：人物 ID + 首见事件。
- 满意招待：人物 ID + 实际来访／结算 ID。
- 对话选择：剧情节点 ID + 实际选择及其发生实例；回看实例禁止写正式关系。
- 线索听说与获得：线索 ID + 对应证据或节点 ID。

### 6.4 线索状态建议

线索可以采用“听说 → 获得证据 → 得到解释”的状态，但实际内容允许多份证据逐步补充，不能只靠一个布尔值。

旧单例子：

1. 首见听到老板娘提起：只记“有旧单”。
2. 资格满足：话题可选，手帐可提示“她似乎愿意谈谈”，不泄露正文。
3. 看过旧单：记录实际看见的字句和物件；不必立即有解释。
4. 后续人物或事件确认：追加解释，保留先前来源。

纸张属于剧情证据，不混入调酒材料库存。是否获得可携带物品由剧情决定；“看过”不等于已经拿走。

## 7. 异常、跳过与旧档规则

| 情况 | 建议行为 |
| --- | --- |
| 教学杯做得不好 | 给真实但不羞辱玩家的回应；继续准备开门，不要求完美杯 |
| 跳过调酒教学 | 使用跳过对白，无假成品、假收益或假满意招待；允许进行轻量采购与关系说明 |
| 直接跳过过渡演出 | 只完成真正允许跳过的引导标记；保留备料入口，不假装与老板娘认识、不写未读线索 |
| 库存已经足够 | 可以认识老板娘而不买东西，采购步骤按“已了解”完成 |
| 资金不足 | 显示真实短缺，允许换准备目标、返回或稍后继续；不暗赠金币、不扣成负数 |
| 误买别的商品 | 正常保留交易与货物，重新提示缺料；不自动回滚合法购买 |
| 原料制作失败或倒掉 | 保持现有真实消耗，不为新手流程自动退回 |
| 米洛首杯不满意 | 仍可建立初识、查看真实记录并结束引导；不虚增好感、不永久锁后续 |
| 首杯触发禁忌 | 按既有逻辑处理拒收、重做或离开；无饮下动画、无虚假付款；关系说明可延后 |
| 切到商店后退出 | 恢复当前阶段，正式交易按既有事务恢复；不重新买一遍 |
| 多次点击签收／翻牌／继续 | 每个剧情动作只生效一次；首客只入队一次 |
| 重看序章 | 剧情回看隔离；商店只读演示，或使用彻底隔离的练习数据，绝不操作正式钱包和库存 |
| 已经营的旧档 | 不强制塞回新教程，不重置故事；提供补看说明与独立回看入口 |
| 旧档新增关系字段 | 保留所有已有解锁和奖励。只从可确认的事件迁移关系；证据不足不伪造数值与过去对白 |
| 查看历史或线索旧内容 | 只读，不重复触发声音、购物、发奖或关系增长 |

老板娘、米洛及其他人的旧版已解锁内容不能因为新关系门槛而重新上锁。当前小游戏应继续由原有条件判断。

## 8. 建议实施顺序和验收

### 第一批：先让开业流程完整

补教学实际结果回应、包裹与递水、备料入口、老板娘初见、翻牌及米洛入场。复用现有商店、仓库、酒单和工作台；CG 以物件叠层及少量动态完成。

验收：新开局能从回响进入实际经营；所有按钮可点击，快捷键与点击一致；库存足够和缺料两种路径都能走通；教学杯与销售杯清楚分开。

### 第二批：让好感与线索有真实依据

新增最小关系事件服务、人物关系摘要、老板娘话头及手帐线索条目。米洛首单关系反馈只依据实际招待事件；教程说明和后台规则一致。

验收：好喝但不合口味、一般但被认真对待、违反禁忌等情况不会被统一写成好感增加；同一事件重试不重复增加；未读内容不出现在手帐。

### 第三批：补一段可验证的后续线索

做老板娘“旧送货单”后续话题，条件达成后出现可选入口，玩家真正阅读才获得证据。这个后续用于证明系统运作，不放到新手流程里强制完成。

验收：条件未达到、已达到未阅读、已阅读三种状态显示不同；直接购物不刷关系；后续证据不重复发放。

### 共同回归项

- 保存并重启后，剧情步骤、钱包、库存、来访与线索一致。
- 开门、首客、结算、关系事件及解锁都可重复检查，但不能重复生效。
- 保留自由调酒、研发、图鉴、手帐与所有已实现小游戏。
- 米洛第二轮、老霍克第三轮的正式邀请仍然成立；艾达与小线旧逻辑不变。
- 历史窗不劫持空格；弹窗输入不穿透；鼠标可以完成全部有按钮的动作。
- 音频保持玩家当前配置，回看和快速切换不叠声。
- 不把开发演示已解锁状态当作正式好感或剧情进度。

## 9. 本轮建议采用的版本与仍可调整的项

建议采用以上完整结构：保留投递员和门口椅子的情绪落点，用老板娘承担采购教学与第一条未解线索，用米洛的真实首单承担“满意度与长期关系不同”的教学。

本轮不需要先定所有角色的好感数值。可以先确认故事与表现，再配置以下事项：

| 项目 | 当前推荐 | 尚未确定 |
| --- | --- | --- |
| 老板娘称呼 | 暂称老板娘，保留白发立绘 | 正式姓名、完整背景 |
| 首个话头 | 留下来的旧送货单 | 背面内容和最终指向可继续润色 |
| 关系界面 | 阶段 + 变化原因 | 是否额外显示数值 |
| 新线索条件 | 关系与具体事件共同判断 | 具体分数、次数、章节门槛 |
| 首批采购 | 基于实际选酒和库存计算 | 正式初始资金、容错备料量 |
| 首单 | 保留米洛真实口味与现有故事 | 发布前校准可负担的候选酒款及匹配表现 |
| 新手完成 | 学会开门并理解记录；不用完美首杯或玩小游戏 | 提示是否完全可跳过的体验细节 |
