# 调酒模式与双模式进度

## 玩家使用

主页左侧菜单下方点击“调酒模式”。进入后按钮变为“剧情模式”，随时点击即可切回。
首次进入调酒模式，需要已挂好酒单，并在剧情中认识至少一位仍可来访的客人。
两种模式仍遵循原有营业时间，白天可提前营业。切走的模式暂停自己的游戏时间。

## 点单与结算

- 顾客从来店时已上架的酒单随机选酒。
- 两种点单方式等概率：直接说酒名，或从所选酒的风味标签中随机选一个标签。没有标签时直接点酒名。
- 指名订单只接受该酒；标签订单接受本次酒单中任何带有该标签的酒。
- 匹配成功且制作评分 ≥ 60：按实际送出的酒收全价。
- 匹配成功但制作评分 < 60：收半价。金币为整数，小数向下取整。
- 不匹配：0 金币，仍记为已送酒，不会阻塞送客。
- 价格来自原材料成本 × 1.5 的现有固定定价规则。
- 订单保存来店时酒单及价格，后续改酒单不会改变这位客人的要求与价格。
- 标签取配方 `tags`，与“完美制作才激活的 buff”是不同数据。
- 调酒模式只进行点单与简短结算反馈，不推进人物故事，不调用 AI 闲聊，不计入小线五次故事送酒的隐藏剧情。

## 立即切换时保存什么

各自保存：当前客人、点单、剧情位置、接待顺序、时间、半成品、桌面材料槽。
共享：金币、实际库存、图鉴、酒单、研发成果、物品及结算记录。
半成品已使用的材料保持消耗，不会在切换时返还或再次扣除。
切换时若正在等待剧情模式 AI 反馈，会取消当前客户端请求；切回后按已有反馈记录继续。
老虎机旋转中须等待本轮结算。

## 存档与接口

- `scripts/play_modes.gd`：PlayModes 自动加载；`switch_to("story" | "mixing")`。
- `scripts/free_drink_order.gd`：无外部服务的点单生成与结算。
- `CustomerService.state.active.play_mode`：本次来访模式。
- `active.free_order`：需求类型、酒 ID、标签、点单文字、来店时酒单。
- 送酒记录 `free_settlement`：matched / full_price / craft_score / amount / tier。
- 新增 `<GameSession.save_path>.modes`，默认 `user://game_session.json.modes`，存放暂停模式及切换日志。
- 活跃模式仍使用既有存档；不修改原有故事 JSON。
- 写入切换日志后才替换各系统状态，意外退出后继续完成切换。
- 设置中的“重新开始”会备份并清空两个模式的进度。

## 接入更多酒

沿用现有 MenuCatalog 酒单接口，必须提供稳定酒 ID、名称、固定售价与 `tags`。DIY 成品一旦纳入该酒单接口即可参与点单；本功能没有另外硬编码五款经典酒名单。
