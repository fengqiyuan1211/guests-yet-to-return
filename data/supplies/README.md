# 原料与器具资料 v1

`catalog.json` 定义 32 项商品：原酒 10、配料 8、装饰品 4、器材 6、杯型 4。独立 `ice` 数组为制作素材，不参与原料库存。

`initial_state.json` 为初始状态模板：原料、装饰库存为零且未点亮；六种器材和四种杯型默认拥有。玩家购买后的状态由唯一 `Supplies` 服务保存到 `user://supplies_state.json`，不修改此模板或商品定义。

商店只有原酒、配料、装饰品，共 22 件可补货商品；`shop_prices.json` 为独立的游戏试用价格。默认器具不售卖，旧存档恢复时会自动补齐，保留材料数量、包装余量和金币。

购买成功和实际消耗后，`Supplies` 将当前总余量同步到 `MenuCatalog.inventory` 并刷新图鉴。配方必需材料及装饰首次买齐后永久点亮，耗尽不退回灰色；当前库存是否足够制作仍单独检查。冰块和可选装饰不参与点亮。

协作对接先看 `docs/物品接口标准.md`；资源与生成说明见 `docs/原料与器具素材接入标准.md`。

图片与完整提示词在 `assets/art/supplies/`，Godot 纹理在该目录的 `textures/`，可操作器材原型场景在 `scenes/supply_assets/`。

来源没有填写的价格和 ABV 保持未知；补货测试采用的草案容量已标记 `game_default_unconfirmed`。鸡尾酒樱桃的含酒状态待核，苦精的 dash 换算仍待确认。

## 工作台液体配色与气泡（2026-10-05 试玩配置）

16 种以 ml 计量的液体均配置 `liquid_appearance`，工作台和成品预览共用同一渲染器。

| 字段 | 含义 |
| --- | --- |
| `rgb` | sRGB 三通道，0–255；作为色素颜色，不代表不透明度 |
| `strength` | 色素强度；透明基酒为 0，不会用白色把混合物染白 |
| `turbidity` | 浑浊程度，0–1；与颜色分开计算 |
| `carbonation` | 视觉气泡强度，0–1；目前苏打水 1、汤力水 0.9、可乐 0.8，其余 0 |
| `color_basis` / `reference_note` | 区分现实近似色与指定的游戏美术色，并保留说明 |

君度使用亮橙色、马拉斯奇诺樱桃利口酒使用粉色，是本作指定的视觉表现。两者实际产品的透明外观不应被这些游戏参数替代：来源可参照 [Cointreau 产品页](https://www.cointreau.com/us/en/products/cointreau) 和 [Luxardo 产品目录](https://www.luxardo.it/wp-content/uploads/2021/05/Catalogo-Liquori-Estero-2021.pdf)。其他原料为近似配色，并非色度测量值；龙舌兰暂按透明类型配置，后续明确商品品类后可调整。

全局透明度、液面提亮、底部阴影和气泡大小/数量/速度集中在 `data/workbench/appearance_rendering.json`。混色仍使用线性光空间的色素量加权；未混合时保留各层颜色。气泡按当前液体体积加权得到强度：含气泡原料占比越低，显示数量越少。上升气泡受酒液形状约束，液面破泡受液面轮廓约束，适配已有杯型及搅拌杯；不在不透明摇壶表面增加色圈。

气泡是程序绘制的动态折射圈和高光，不是材料图标。它只影响画面，不改变材料用量、库存、酒精度、评分或研发资源。首版没有模拟静置跑气、温度、摇晃后的气压和泡沫，也没有独立的每层气体储量；后续如要纳入玩法，应增加独立状态，不能从画面粒子反推数值。

正在制作的半成品进入工作台时会更新原料外观快照，不改动作、容器内容或消耗记录。已完成记录仍保留原始 RGB 快照；旧快照没有 `carbonation` 时对三种已知含气泡原料兼容补值。整体亮度等全局画面设置对新旧记录都生效。

工作台四个盛液容器（成品杯、搅拌杯、摇壶、量酒器）现已支持 12 个方向的拖动互倒。盖好的摇壶通过内置滤网出液；作为接收容器时需要开盖。不用滤网时按容量转移酒液、冰及配料，空间不足的部分保留在源容器。转移不重复扣库存，重复命令不重复执行，写盘失败时两边内容一起回滚。

回归入口：`tests/verify_vessel_transfers.tscn`，必须使用独立 `/tmp` 测试存档参数；另有 `tests/run_workbench_liquid.py` 和 `tests/run_research.py` 可自动创建隔离存档。新增检查覆盖所有拖动方向、容量截断、保存失败回滚、旧外观快照、含气泡原料识别、稀释、不同杯型边界及画面动画不修改制作状态。

## B 版薄荷、柔化分层及桌面轮换

薄荷工作台显示现使用 `assets/workbench/mint/mint-b-leaf.png`；制作方式与完整提示词见该目录 README。共享商品原图保持不变，备料柜中的薄荷和薄荷枝由工作台统一绘制组件显示。

分层衔接改为带透明度的连续颜色过渡，采用预乘透明度的线性光混色，减少白边；交界有轻微弯曲和动态起伏。`appearance_rendering.json` 的 `layer_edges` 配置控制过渡宽度、相邻层厚度限制、波动幅度及横向网格密度。搅拌时过渡适度加宽，颜色仍跟随真实各层的混合结果；并不把视觉渐变写回原料用量或层记录。

桌面新增 `WorkbenchSession.place_table_material(id)` 入口：不足五瓶则追加，满五瓶时原子替换最早摆上的一瓶。已在桌上的瓶子不重复、不调整先后次序。空库存/未知原料不挤掉旧瓶，保存失败保留原摆放。`set_table_materials` 仍严格验证上限和重复项，兼容现有手动收回及恢复接口。进入量取时禁止重复开启另一次量取，避免打断正在倒酒的瓶子。轮换及收回只影响摆放，不消耗或返还库存。

相关验证：`tests/verify_workbench_b_polish.tscn`、更新后的 `verify_workbench_drag.tscn`；前者覆盖第六瓶自动替换、反复选取、无库存/写盘失败、量取保护、恢复、分层连续性、薄层宽度、透明素材和动画不改制作事实。可用 `python3 tests/run_workbench_b_polish.py --godot /path/to/Godot --graphics` 在独立临时存档中复现并生成截图。
